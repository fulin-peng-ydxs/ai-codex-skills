# 页面原型设计

将需求中的页面结构、操作链路和状态反馈转为可查看、可操作的 HTML 原型。可以独立使用，不要求先生成正式 `requirement.md`。

## 输入与职责

- 读取用户指定的需求、已确认闭环、现有原型和相关页面；继承功能范围、角色、权限、状态和确认结论。已有需求编号时保留映射，没有编号时按页面功能点追溯，不为原型额外编写 PRD 或分配正式需求编号。
- 读取目标项目适用的 `AGENTS.md`、`DESIGN.md` 和同类页面。需要视觉或交互方案时配合 `frontend-design`；本技能负责原型产物与交接，视觉原则不重复维护。
- 缺少影响业务成立的规则时先澄清；有明确依据的局部布局细节自行处理。用户要求先做探索草案时可以使用标明的假设，但不能把假设写成已确认需求。
- 仅要求原型时不修改生产页面、生成开发计划或重写需求文档。正式 PRD 交给 `requirement-doc-generator`；仅审核已有页面体验时使用 `page-ux-audit`。

## 页面范围与输出

- 用户明确指定原型页面、保真度、格式或位置时优先遵循。默认产物为可在浏览器查看的 HTML，交互只模拟需求范围内的行为，不连接真实业务写入接口。
- 为新增页面制作对应原型；更新页面涉及主要区域新增、布局重排、跨组件联动、复杂表单/表格/图表、工作台、配置或可视化状态时，制作更新后页面或变更区域原型。普通文案、字段、小按钮、简单显隐、局部校验或低风险提示无需自动生成原型，除非用户明确要求。
- 有需求文档时，默认放在该文档所在目录的 `prototypes/{page-slug}.html`；独立制作时按全局协作规则确定本次需求目录，在其 `prototypes/` 下保存。页面命名使用稳定业务语义，复用已有同一需求目录和有效原型。
- 写入前检查已有文件。只更新本次授权页面，保留有效布局和交互；用户仅要求查看或提出方案时不覆盖产物。
- 先说明页面清单、输出位置、关键布局和仍需确认事项。沿用会话中已有确认，不重复请求批准；需要新增关键交互决策时给推荐方案和理由，确认后实现。由需求文档技能调用时，继承其页面清单和确认结果。

## 制作与衔接

- 先确定页面入口、主要区域、操作顺序、数据展示、弹窗/抽屉与返回路径；按业务需要覆盖加载、空、错误、权限、成功及失败恢复状态，不机械增加无关状态。
- HTML 使用完成评审所需的最小结构与模拟数据；默认可直接打开，确需本地服务或额外依赖时说明启动方式。布局表达固定区、滚动区及目标终端下的响应式或低高度退化策略。
- 交互反馈需要表现用户操作后的可观察结果，例如提交后的校验、成功或失败状态、列表更新和返回路径；无需实现真实后端。演示结果不得宣称生产能力已实现。
- 原型与需求冲突时指出差异，不能以原型静默改变范围或业务规则。只做原型时报告需求引用需要更新的位置；需求文档技能调用时由其将实际产物路径回填页面条目。

## 原型呈现与交互规则

- HTML 原型必须服务于需求澄清和后续开发理解，优先参考项目已有前端风格、DESIGN文档、组件库、布局密度、导航结构、表格/表单/弹窗模式和视觉规范；如果项目缺少可参考风格，采用克制、可实现、便于开发理解的低保真布局，不要把营销页、装饰性视觉或无关交互动效写入业务原型。
- 正式业务控件必须与需求定义的实际功能一致；出现按钮、菜单、筛选、提交、弹窗、抽屉、切换、联动、状态变化等交互元素时，必须提供对应的可用交互反馈，不能放置看似可用但无行为的功能控件。
- 无法实现或暂不纳入的交互必须禁用或显著标注为暂不实现，不得和正式可用操作使用同一视觉层级。
- 用于解释业务规则、字段含义、流程原因、验收口径或开发注意事项的内容，必须用区别于正式业务界面的颜色、边框、背景或标签样式标识为“原型说明/开发说明”，并避免伪装成真实页面文案、提示条、表单字段或业务组件。
- 仅用于评审演示状态或辅助理解的控件，必须放在“原型说明/开发说明”等批注区域内，按钮文案显式包含“原型演示”或同等标识；不得放入正式业务工具栏、筛选区、表单、表格操作列或页面主命令区。
- 如果原型提供隐藏批注能力，所有原型说明、开发说明和原型演示控件必须随批注一起隐藏，确保开发实现时能清晰区分线上功能和评审辅助内容。
- 原型辅助内容不能改变需求范围；真实线上功能仍以需求编号、页面功能点、验收标准和页面布局模板中的描述为准。
- 原型复核只检查它是否正确承载已定义的页面结构、操作链路、状态反馈、权限边界和关键数据口径；演示数据的数量、名称、排序结果等只有在用于证明业务规则或验收口径时才需要核对，不能把原型评审变成模拟数据实现审查。

## 验证与交付

- 先从业务使用者和接手开发者视角走读一条主链路及相关失败路径，核对页面功能、状态、权限和需求范围，修复遗漏与误导控件。
- 读取 [前端验证规范](~/ai-agent-config/config/force/frontend-verification.md)，按共用方法选择并实测本次原型的相关场景，记录证据、结果和未验证项；不因制作原型扩大为生产页面或全站验收。
- 原型专项检查：有隐藏批注开关时确认说明及演示控件一并隐藏；检查相对链接和资源可用，以及演示行为是否正确承载需求。模拟反馈只能证明原型交互，不证明真实接口、权限或持久化已实现。
- 交付原型文件链接、查看方式、已验证的链路与遗留事项；区分原型完成、用户确认和生产实现状态。不额外创建过程报告。
