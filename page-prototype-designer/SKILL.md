# 页面原型设计

## 输入与职责

执行前读取 [需求协作共用契约](../requirement-doc-generator/references/workflow-contract.md)，应用事实继承、确认和已有成果规则；本技能负责原型呈现与模拟交互，不要求先有正式 PRD，也不因共用契约而额外编写需求文档或技术方案。

- 读取用户指定需求、闭环、现有原型和相关页面，继承范围、角色、权限、状态和确认结论；已有需求编号就保留映射，没有则按页面功能点追溯，不另编 PRD 编号。
- 读取适用的 `AGENTS.md`、`DESIGN.md`、同类页面及组件模式；需要视觉或交互方案时配合 `frontend-design`，视觉原则不重复维护。
- 缺少影响业务成立的规则时处理相关阻塞；局部布局按依据自行决定，探索草案可用明确标注的假设。原型与需求冲突时说明差异，不静默改范围或业务规则。
- 仅要求原型不修改生产页面、不生成开发计划或重写需求；只做原型时报告需求引用需更新的位置，由需求技能调用时交回实际路径及验证状态。

## 页面范围与输出

- 用户指定的页面、保真度、格式和位置优先。默认使用可直接在浏览器打开的 HTML 与模拟数据，不连接真实业务写入接口；确需服务或依赖时说明启动方法。
- 新增页面制作对应原型；更新涉及主要区域新增、布局重排、跨组件联动、复杂表单/表格/图表、工作台、配置或可视化状态时，制作更新后页面或变更区域原型。普通文案、字段、小按钮、简单显隐、局部校验、低风险提示无需自动制作，用户明确要求时仍制作。
- 默认放需求文档同目录的 `prototypes/{page-slug}.html`；独立原型按全局规则确定需求目录。使用稳定业务命名，复用同一需求的有效原型；已有文件按共用契约判断更新，不另建平行版本。
- 先说明页面清单、路径、关键布局和未决项；沿用已有授权与确认，不重复批准。只查看或提方案不覆盖文件，只修改授权页面并保留有效布局与交互。

## 制作与呈现

- 先确定入口、主要区域、操作顺序、数据展示、弹层和返回路径，按业务覆盖加载、空、错误、权限、成功及失败恢复；不机械添加无关状态。布局表达固定/滚动区域、长内容及目标终端的响应式或低高度退化。
- 使用完成评审所需的最小结构，优先沿用项目风格、导航、布局密度和表格/表单/弹层模式；无依据时采用克制、可实现的低保真布局，不加入无关营销装饰或动效。
- 正式业务控件与需求一致：按钮、筛选、提交、弹层、切换、联动和状态变化必须有可用、可观察的模拟反馈，如校验、成功/失败、列表更新和返回；不能出现看似可用却无行为的控件。无法演示或未纳入的交互须禁用或显著标注，不与可用操作混淆。
- 解释业务规则、字段、流程、验收或开发注意事项的辅助内容以颜色、边框、背景或标签明确标为“原型说明/开发说明”，不得伪装成真实业务文案、字段或提示组件。
- 评审状态切换等辅助控件仅放批注区，文案含“原型演示”或同等标识，不进入正式业务工具栏、筛选、表单、表格操作列或主命令区。有隐藏批注功能时，说明与演示控件须一起隐藏。
- 辅助内容不增加线上功能，业务以已确认需求、页面功能点、验收和布局约束为准；无正式 PRD 时以当前有效输入为准。模拟结果不代表生产接口、权限或持久化能力已实现。

## 验证与交付

- 从业务使用者和接手开发者视角走读主链路及相关失败路径，检查结构、操作、状态、权限和数据口径，修复遗漏及误导控件。演示数据的数量、名称和排序只在承载业务规则或验收时核对，不扩展为模拟实现审查。
- 读取 [前端验证规范](~/ai-agent-config/config/force/frontend-verification.md)，实测本次相关场景，记录证据、结果和未验证项；检查相对链接、资源、批注隐藏及演示行为，不扩大为生产页面或全站验收。
- 交付文件链接、查看方式、已验证链路与遗留问题；区分原型完成、用户确认和生产实现，浏览器验证受限时明确缺口，不宣称通过，不额外建过程报告。
