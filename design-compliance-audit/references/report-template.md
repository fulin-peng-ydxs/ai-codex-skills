# 设计合规报告模板

本文件维护报告默认骨架和字段；审查范围、定级规则及完成标准由 [技能入口](../SKILL.md) 维护，具体检查项由 [合规清单](compliance-checklist.md) 维护。首次形成完整审核结论时读取；仅保存或局部更新保留原成果及证据状态。

按 [文档结构与输出规范](~/ai-agent-config/config/force/document-output.md) 使用**默认骨架**，以问题为审阅及复核单元。文档与实现的独立结论、范围、事实源、定级和类别保持；同根因跨类别时合并说明全部影响及各自判据，不以体验等级覆盖合规等级。

```md
## 结论与范围

- DESIGN 文档：通过 / 不通过 / 需要补齐 / 未审查
- 实现遵循：通过 / 不通过 / 需要补齐 / 无法判断 / 未审查
- 页面 / 模块 / 文件：
- DESIGN 事实源与适用版本：
- 审查方式：静态 / 实测 / diff 对照
- 视口范围：
- 是否检查移动端：是 / 否，原因：

## 问题与复核

### {问题编号} [P0/P1/P2/P3] {标题}

类别：DESIGN 文档自身问题 / 实现违反硬规则 / 默认规范偏离 / 维护闭环缺口。

{就近说明 DESIGN 规则或文档位置、项目证据、实现位置与现象、为何不合规及影响；文档问题与实现问题分别按技能入口定级。}

{最小修复方向及需要同步的事实源/注册/schema/token/测试/文档，复核所需条件、操作及符合契约的预期结果。记录实际已运行/未运行及原因、证据与当前状态；建议不等于已修复。}

{适用的已确认例外及依据、疑似 DESIGN 过时或冲突、需用户确认的偏离及影响，放在所属问题旁。}

## 覆盖与剩余事项

{按契约或页面/状态概括已检查范围及结果，正常项也有覆盖说明；共用验证环境、已运行/未运行及原因、未审查与无法判断的部分。条目已有证据仅引用。}

{跨问题的例外、冲突和未决事项及正文定位；无问题时省略空问题条目，仍保留文档与实现独立结论、检查范围和证据限制。}
```
