# 研究基线与持续维护

## 模式、存储与授权边界

模式由[主入口](../SKILL.md#执行流程)决定，完整范围、比例类型及缺数传播由[数据契约](data-contract.md#模块依赖和阻断传播)维护。跟踪从有效完整基线及后续更新起步，只解释增量，内部核验下文全部类别。完整研究与跟踪默认保存报告并维护档案；明确只对话、不保存时尊重限制。专项问答默认不改档案，只保存已有成果时不更新研究截止。维护档案不等于授权交易、外发消息或创建定时任务。

保存位置优先使用用户路径、现有公司研究目录、所属投资项目的 `agent-works/stock-research/<交易所>-<代码>/`。无投资项目时使用 `~/investment-research/<交易所>-<代码>/`，执行前告知实际路径，不把当前技能仓库当研究项目。身份以交易所、代码、法人主体关联，代码更名核验后登记，不因简称改变另起一份断链档案。

每家公司只维护一个状态入口，按需要创建下列真实产物，不造空目录：

- `state.md`：当前可用结论、最后核验时点、缺口、基线及完整已提交研究索引；按本文件唯一模板。
- `reports/<run-id>-full.md`：完整报告或未完成的完整研究尝试；是否完整以内容门槛判定。
- `updates/<run-id>.md`：季报/事件增量和受阻更新记录。
- `evidence/<run-id>/`：原始资料与标准化数据；来源记录遵循数据契约。`data.json` 保存数据记录数组，`calculations.json` 保存计算 ID、公式、输入 ID、输出和方法版本，`dependencies.json` 保存分析项 ID、原始必需输入 ID、必需上游项 ID、父模块、启用模式、状态及阻断原因；V另记录价值起点及所选模型，A/P记录各档参数、证据及分配依据核验时点；个性化配置另记录用户约束时点，完整研究与跟踪均标为必需。这些是资料记录格式，不是自动计算系统；状态提交工具只处理文件并发与时点保护，不核验投资分析。

run-id 使用执行时区的时间戳加短唯一后缀；报告头同时写研究截止时点，不用文件名代替。只有完整且通过核验的报告才能成为 active baseline。未完成的建档尝试可保存证据与缺口，但状态为“待建立”，不得借此启动比较性跟踪。

## 历史回看与当前时间线

先区分执行时间与研究截止。用户明确指定过去时点的回看、回测或历史重建，报告和证据写入 `history/<截止日期>/<run-id>/`，沿用原完整/专项范围与相应模板；只使用当时已公开资料。历史任务不创建或替换当前 `state.md`、active baseline、最近更新、当前缺口及调度状态，即使历史报告资料齐全，或当前档案尚未建立，也只形成历史成果，不获得当前完整基线资格。不把2026年事实用于2023年回看。

普通当前研究提交的截止时点不得早于当前state；较早任务后完成时也不得覆盖较新状态，转存历史/过时尝试并说明未应用，不把其截止日期改为今天。相同截止时点的更正允许提交，但须核验修订证据、说明更正原因并保留被替代记录；按涉及内容决定受影响重算或需重建。先后次序不由运行文件名或完成时间代替。当前基线已失效时也不自动回退采用较旧报告。

## 已提交研究索引与读取顺序

`state.md` 的固定索引表是当前时间线唯一提交索引，列出所有已提交完整研究尝试及增量记录，不只保存最新一条。每条记录包含运行ID、类型、研究截止、所属完整基线ID、前次已提交记录ID、产物链接和用途状态；首次前次为“无”，无有效基线为“无（原因）”。历史回看仅在自身目录归档，不加入当前索引。旧基线及其更新保留索引行，不随新基线建立而删除；受阻记录可列入，但不能因此获得完整基线资格。

读取时先读state并核验索引，再载入当前有效完整基线，然后沿前次关系读取该基线之后的全部记录，最后核验引用证据；最近更新字段指向最近已提交的增量记录，当前基线字段独立指向有效完整报告。无当前基线不得因存在索引启动比较性跟踪。相同截止时间按链顺序读取，不按目录排序猜测。索引断链、循环、重复ID、错误基线归属或文件缺失时停止依赖此链的比较和状态推进，保留独立事实并报告缺口。

旧state缺索引时，可以扫描已有报告作恢复取证，但须逐份核实主体、时点、基线和前次关系后构建索引；无法确定的顺序不得猜补。尚未被state引用的文件视为未提交尝试，不能因存在就自动加入有效更新链。恢复索引是存储迁移，不改变方法1.3及有效完整基线门槛，不新增模块级基线。

## 建立与恢复基线

完整基线必须通过[数据契约完整判据](data-contract.md#模块依赖和阻断传播)。记录方法版本、证券主体、财务与价格时点、依赖和证据版本、评分明细、核心假设、完整计划、风险及催化剂，随报告加入已提交索引。旧报告按[版本迁移规则](methodology.md#适用性与方法版本)核验范围与计算；缺原必需模块或采用已变评分口径时需重建，不能沿用完整标签。可复用仍有效且口径未变的证据和经核验计算；规则多档命中或未覆盖属于规则错误，不改成数据缺口掩盖。

按上节顺序读取，不能只靠聊天记忆或摘要。无state但有完整可靠报告时，核验完整性、证据、时间线与索引后可恢复档案；无可用完整基线时，停止比较性跟踪的“变化、维持、上调、下调”判断，保存已有独立事实与缺口。仅请求跟踪不自动完成重建；明确要求完整研究才执行完整流程。不允许部分模块自行成为跟踪基线。

## 每次跟踪必须检查

| 类别 | 最低检查内容 | 允许复用和阻断边界 |
| --- | --- | --- |
| 财报与经营 | 最新三大报表、附注、更正，单季同比/环比所需期间，分部与经营 KPI | 确认未有新披露可复用原快照；发布了新数据却获取不到不能沿用旧值当当前 |
| 价格与资本结构 | 最新收盘、停复牌、分红除权、股本、融资、回购及债务变化 | 除权/增发须重算每股值和价格条件；不能直接比较未调整旧价 |
| 预测与估值 | 预测机构、窗口、年度滚动、分歧；当前倍数、历史位置、同业、V的输入与价值路线 | 预测过期或共同样本不足阻断未来判断及相关评分；某子项缺数沿其真实消费方传播，参数实际引用了预测/历史/同业的V同样阻断，不能用旧值维持 |
| 驱动与行业 | 已登记驱动的最新发布、历史位置、竞争格局及政策事件 | 无新一期要有发布日核验；查询失败属于未知而非持平 |
| 风险与治理 | 期间公告、审计、问询/监管、诉讼、担保、关联交易、人员与控制权变动 | 保留检索日期/范围；重大未决问题阻断相应综合与行动判断 |
| 假设与计划 | 每条投资逻辑、证伪信号和未来 6—12 月催化剂；三档 A/P 的价格、分配依据、损失情景、触发与证伪状态；个性化方案另查用户持仓约束 | 全部真实依赖已核验才可判未触发或维持；缺一项标待核验，不沿用旧比例。原报告缺少 A/P 时按基线不完整处理，不作为免查理由；公开研究计划不臆造私人组合 |

财报/公司事件按公告从上次核验时点覆盖到本次截止时点；方法未变、未重述的历史数据可直接复用，仍记录本次检查的依据。只取新增或失效需要刷新的数据，只重算受影响项，不重复下载全部十年资料。年度滚动时更新十年覆盖、五年评分和前瞻年度。交付保留原五段：本季度速览、驱动因子变化、打分复核、建仓计划复核、结论；正文不超过基线完整报告正文的 1/3，详细证据及缺口在档案中维护并链接。无新季度时说明检索依据，不造速览数据。

## 状态迁移与更新规则

- 档案状态为“待建立”“可用”“部分待核验”“需重建”“归档”；结论状态为“已复核”“待核验”“已证伪”“不适用”。“可用”只表示截至标注时点，不承诺实时监控。
- 跟踪所需数据缺失时，仍可保存已核验的新事实、缺口及无依赖结论，但标记受影响条目待核验，档案为部分待核验；阻断总体维持判断及依赖该缺项的结果和行动。任一评分依赖未核验即阻断全部当前汇总分；若全部评分依赖已核验而其他核心受阻，仅可列已复核筛查分，不代表整体判断维持。受影响的旧结论只留作带日期历史值，不当作当前有效结果。
- 缺失补齐后重算全部受影响依赖，附补齐来源；全套必查类别覆盖完整且门槛通过，才恢复可用。“需重建”不会仅因一个缺口补齐而转可用或部分待核验，必须完整重建通过。新证据已证明证伪时及时标记，不因其他数据缺失掩盖已证实负面事实。
- 重大重组、主营切换、会计口径断裂、关键财报重述、核心模型/方法版本变化或原估值逻辑失效，标需重建；停止总体增量结论和旧方案执行判断。此时清空当前有效基线指向，基线记录保留原报告链接并明确“历史完整、当前已失效”，不能仍标当前有效。可输出独立事实及变更影响；完整重做通过后设置新 active baseline，保留旧版链接。模型失效不自动等于每条逻辑已证伪，逐条按证据判断。
- 重建不自动删除原报告；用户明确要求完整重做可直接执行。仅请求增量时，先交付重建原因与已核实变化，不擅自把缺失的重建结果写入状态。
- 每次维护稳定的 `T-` 逻辑、`R-` 风险、`C-` 催化剂、`G-` 缺口标识；新增或失效保留状态和历史引用，不因表格排序重编号。实际观察、推断窗口与已公告日期分别标注。
- 用户归档后停止自动维护；仅在其要求恢复或修改时继续。取消定时任务需通过实际自动化工具另行核验，修改 state 不等于调度已取消。

## 写入一致性与下一次触发

当前state写入必须使用[状态提交工具](../scripts/publish_state.py)，运行环境为支持本机 `fcntl.flock` 的 Python 3 / POSIX 本地文件系统。所有写入者共用公司目录的 `.state.lock`，不能用直接写文件、仅比较后重命名或删除锁文件绕过。共享网络盘、非POSIX环境或锁语义不能确认时停止state提交，保留报告草稿并说明维护未完成，不降级为无锁写入。

1. 读取当前state原始字节并记录SHA-256；不存在则记 `absent`。据此载入索引、基线及后续记录。先生成唯一运行ID的不可变报告、证据和计算记录，再生成候选state，包含旧完整索引和本次新增记录。提交前检查格式、链条、证据引用及数据门槛；不能覆盖已有运行产物。历史回看不进入此步骤。
2. 候选与当前state的“研究截止”字段使用带时区ISO 8601时间（如 `2026-11-23T10:00:00+08:00`），其他日期在资料覆盖字段记录。旧state时间格式不能解析时，先从原证据核实同一截止时刻及其时区，再执行工具的 `--normalize-time <原截止的ISO时间> --expected <原哈希> --directory <公司目录>` 分支（不传candidate）。此分支仅替换现有截止字段，保留其他字节内容，不允许用于已规范化时间或新建state；无法核实原时刻就保持受阻，不猜时区、不升级截止。工具不能证明人工提供的等价时刻正确，必须单独核对证据。
3. 执行 `python3 <技能目录>/scripts/publish_state.py --directory <公司目录> --candidate <候选state路径> --expected <原SHA-256或absent>`。工具在公司锁内重读state，核对原哈希及研究时点不倒退，写入临时文件、同步、原子替换并回读。默认锁等待5秒，最多60秒；超时退出，不抢占活跃锁。
4. 哈希冲突时不提交候选；重新读取最新state、链与证据，按新的状态合并本次独立记录、重算受影响结论、重做验证后生成新候选。禁止只刷新expected哈希后重试旧内容。当前更晚时按历史/过时尝试处理，不能合并较旧判断覆盖当前内容。同截止更正也必须基于最新状态。
5. 回读工具返回哈希及state，核对基线、最近更新、完整索引和条目状态后才称维护完成。工具不代替投资语义与模板校验。替换前失败保留原state；替换后响应丢失或异常时先回读：候选字节已成为state则核实链后视为已提交，不重复追加；否则保留未提交产物并重新核验。

锁由操作系统随持锁进程退出释放，`.state.lock` 文件本身可以长期存在，不能据文件存在或年龄判为死锁，更不能删锁让两个写入者分别锁住不同文件。进程崩溃留下的 `.state-write-*.tmp` 不属于已提交状态，恢复时不从它自动更新指针；只在取得同一公司锁、确认未被使用并核实本次归属后清理对应临时文件，报告及原始证据不随之删除。工具退出码0表示本次提交并回读成功，3为版本冲突，4为锁超时，5为时点/时间格式不满足，其他失败保留现场并检查实际state。进程在原子替换后崩溃也必须按回读结果恢复，不能仅看退出状态断言未提交。

每次明确下次触发：公司已公告披露日期、关键经营数据发布、重大事件或明确复核日；没有确定日期则记事件条件和待确认窗口，不把法定最后期限当实际披露日。需要自动运行时由用户单独指定频率、时区和通知要求，使用宿主自动化工具；维护 state 中实际返回的任务标识与状态，不虚构后台任务。敏感组合信息仅在仓位模块需要且用户提供时保存最小必要内容。
