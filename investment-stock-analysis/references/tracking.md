# 研究基线与持续维护

## 模式、存储与授权边界

明确要求完整或重做时重新审视所有核心模块及三档建仓计划；未另指定模式且已有可核验完整分析时默认跟踪。跟踪从完整基线及后续更新起步，只解释增量，但内部检查下文所有必查类别，包含原三档价格、触发、比例及证伪条件，不要求用户再次点名。完整研究与跟踪默认保存报告并维护研究档案；明确只对话、不保存时尊重限制。专项问答不会自动改动档案，只保存时不更新截止时点。维护档案不等于授权交易、外发消息或创建定时任务。

保存位置优先使用用户路径、现有公司研究目录、所属投资项目的 `agent-works/stock-research/<交易所>-<代码>/`。无投资项目时使用 `~/investment-research/<交易所>-<代码>/`，执行前告知实际路径，不把当前技能仓库当研究项目。身份以交易所、代码、法人主体关联，代码更名核验后登记，不因简称改变另起一份断链档案。

每家公司只维护一个状态入口，按需要创建下列真实产物，不造空目录：

- `state.md`：当前可用结论、最后核验时点、缺口、基线及更新索引；按本文件唯一模板。
- `reports/<run-id>-full.md`：完整报告或未完成的完整研究尝试；是否完整以内容门槛判定。
- `updates/<run-id>.md`：季报/事件增量和受阻更新记录。
- `evidence/<run-id>/`：原始资料与标准化数据；来源记录遵循数据契约。`data.json` 保存数据记录数组，`calculations.json` 保存计算 ID、公式、输入 ID、输出和方法版本，`dependencies.json` 保存分析项 ID、原始必需输入 ID、必需上游项 ID、父模块、启用模式、状态及阻断原因；V另记录价值起点及所选模型，A/P记录各档参数、证据及分配依据核验时点；个性化配置另记录用户约束时点，完整研究与跟踪均标为必需。只是维护格式，不是已存在的自动计算系统。

run-id 使用执行时区的时间戳加短唯一后缀；报告头同时写研究截止时点，不用文件名代替。只有完整且通过核验的报告才能成为 active baseline。未完成的建档尝试可保存证据与缺口，但状态为“待建立”，不得借此启动比较性跟踪。

## 建立与恢复基线

保存完整基线时记录方法版本、证券主体、基线截止时点、财务和价格日期、分析项依赖、数据版本、15 项明细、核心假设、证伪阈值、V、完整三档建仓计划 A/P、风险与未来 6—12 个月催化剂。旧报告按[版本迁移规则](methodology.md#适用性与方法版本)核验范围与计算；缺 A/P、十年三表或采用已变评分口径时标需重建，不能沿用完整标签或“未请求”规避。可复用仍有效且口径未变的证据和经核验计算；全部当前门槛通过后建立新基线。数据齐全而评分多档命中或无档可选属于规则错误，记录并阻断，不改成数据缺口掩盖。

跟踪先读 state、基线报告和其后的更新，再检查所引用证据是否可读。不要依赖聊天记忆或只读摘要。无 state 但用户提供完整可靠报告时，可校验方法与依赖后恢复档案；不完整则报告缺口。无可用基线时停止“变化、维持、上调、下调”判断，返回受阻说明并维护已有独立事实与缺口；仅请求跟踪不自动冒充完成完整重建，明确要求完整研究时执行完整流程。

## 每次跟踪必须检查

| 类别 | 最低检查内容 | 允许复用和阻断边界 |
| --- | --- | --- |
| 财报与经营 | 最新三大报表、附注、更正，单季同比/环比所需期间，分部与经营 KPI | 确认未有新披露可复用原快照；发布了新数据却获取不到不能沿用旧值当当前 |
| 价格与资本结构 | 最新收盘、停复牌、分红除权、股本、融资、回购及债务变化 | 除权/增发须重算每股值和价格条件；不能直接比较未调整旧价 |
| 预测与估值 | 预测机构、窗口、年度滚动、分歧；当前倍数、历史位置、同业、V的输入与价值路线 | 预测过期或共同样本不足阻断未来判断及相关评分；某子项缺数沿其真实消费方传播，参数实际引用了预测/历史/同业的V同样阻断，不能用旧值维持 |
| 驱动与行业 | 已登记驱动的最新发布、历史位置、竞争格局及政策事件 | 无新一期要有发布日核验；查询失败属于未知而非持平 |
| 风险与治理 | 期间公告、审计、问询/监管、诉讼、担保、关联交易、人员与控制权变动 | 保留检索日期/范围；重大未决问题阻断相应综合与行动判断 |
| 假设与计划 | 每条投资逻辑、证伪信号和未来 6—12 月催化剂；三档 A/P 的价格、分配依据、损失情景、触发与证伪状态；个性化方案另查用户持仓约束 | 全部真实依赖已核验才可判未触发或维持；缺一项标待核验，不沿用旧比例。原报告缺少 A/P 时按基线不完整处理，不作为免查理由；公开研究计划不臆造私人组合 |

财报/公司事件按公告从上次核验时点覆盖到本次截止时点；方法未变、未重述的历史数据可直接复用，仍记录本次检查的依据。只取新增或失效需要刷新的数据，只重算受影响项，不重复下载全部十年资料。年度滚动时更新十年覆盖、五年评分和前瞻年度。交付保留原五段：本季度速览、驱动因子变化、打分复核、建仓计划复核、结论；正文不超过基线完整报告正文的 1/3，详细证据及缺口在档案中维护并链接。无新季度时说明检索依据，不造速览数据。

## 状态迁移与更新规则

- 档案状态为“待建立”“可用”“部分待核验”“需重建”“归档”；结论状态为“已复核”“待核验”“已证伪”“不适用”。“可用”只表示截至标注时点，不承诺实时监控。
- 跟踪所需数据缺失时，仍可保存已核验的新事实、缺口及无依赖结论，但标记受影响条目待核验，档案为部分待核验；阻断总体维持判断及依赖该缺项的结果和行动。任一评分依赖未核验即阻断全部当前汇总分；若全部评分依赖已核验而其他核心受阻，仅可列已复核筛查分，不代表整体判断维持。受影响的旧结论只留作带日期历史值，不当作当前有效结果。
- 缺失补齐后重算全部受影响依赖，附补齐来源；全套必查类别覆盖完整且门槛通过，才恢复可用。“需重建”不会仅因一个缺口补齐而转可用或部分待核验，必须完整重建通过。新证据已证明证伪时及时标记，不因其他数据缺失掩盖已证实负面事实。
- 重大重组、主营切换、会计口径断裂、关键财报重述、核心模型/方法版本变化或原估值逻辑失效，标需重建；停止总体增量结论和旧方案执行判断。此时清空当前有效基线指向，基线记录保留原报告链接并明确“历史完整、当前已失效”，不能仍标当前有效。可输出独立事实及变更影响；完整重做通过后设置新 active baseline，保留旧版链接。模型失效不自动等于每条逻辑已证伪，逐条按证据判断。
- 重建不自动删除原报告；用户明确要求完整重做可直接执行。仅请求增量时，先交付重建原因与已核实变化，不擅自把缺失的重建结果写入状态。
- 每次维护稳定的 `T-` 逻辑、`R-` 风险、`C-` 催化剂、`G-` 缺口标识；新增或失效保留状态和历史引用，不因表格排序重编号。实际观察、推断窗口与已公告日期分别标注。
- 用户归档后停止自动维护；仅在其要求恢复或修改时继续。取消定时任务需通过实际自动化工具另行核验，修改 state 不等于调度已取消。

## 写入一致性与下一次触发

写前读取状态版本/摘要；先写新报告、证据与计算记录并检查引用，再以临时文件替换 state，最后回读核对 active baseline、last update 和条目状态。写入中断不得宣称维护完成；保留原有效指针及本次未完成记录，恢复时检查已有产物，避免重复写入。更新前发现 state 已被其他运行修改，重新读取合并；不能用旧快照覆盖并发结果。

每次明确下次触发：公司已公告披露日期、关键经营数据发布、重大事件或明确复核日；没有确定日期则记事件条件和待确认窗口，不把法定最后期限当实际披露日。需要自动运行时由用户单独指定频率、时区和通知要求，使用宿主自动化工具；维护 state 中实际返回的任务标识与状态，不虚构后台任务。敏感组合信息仅在仓位模块需要且用户提供时保存最小必要内容。
