# 研究基线与持续维护

## 模式、存储与授权边界

模式由[主入口](../SKILL.md#执行流程)决定，完整范围、比例类型及缺数传播由[数据契约](data-contract.md#模块依赖和阻断传播)维护。完整研究和跟踪默认保存；仅对话、不保存或专项问答遵守用户范围。仅保存已有成果不重新调研、不改研究截止。维护档案不等于授权交易、外发消息、Git提交/推送或创建定时任务。

保存位置优先使用用户指定目录和现有公司目录；专用研究仓库使用 `<交易所>-<代码>/`，其他投资项目默认 `agent-works/stock-research/<交易所>-<代码>/`，无项目时用 `~/investment-research/<交易所>-<代码>/`。执行前说明实际路径，不把技能仓库当研究项目。身份以交易所、代码和法人主体关联，简称变化不另建重复档案。

每家公司只维护一份最新报告和一套当前支撑资料：

- `report.md`：唯一最新研究报告；完整研究、补缺、季报及事件更新均直接更新本文件。不按日期或运行另存完整报告、增量报告、备份、旧稿或快照目录。
- `state.md`：当前结论、完整研究资格、核验时点、缺口、当前产物及校验值；仅记录当前状态，不维护历次报告索引或更新链。按本文件唯一模板。
- `evidence/`：原始资料和当前标准化数据。原始年报、公告等按文档身份命名，未变且仍有效的文件直接复用；不同报告期的原始财报是分析输入，不是报告备份，不为去重删除实际使用的历史财报。当前 `data.json`、`calculations.json`、`dependencies.json`、`gaps.json` 及来源索引直接更新，不按运行复制整套资料。

数据记录格式遵循数据契约。`calculations.json` 记录计算ID、公式、输入ID、输出和方法；`dependencies.json` 记录原始必需输入、必需上游、父模块、模式、状态和原因；V记录价值起点及模型，A/P记录各档参数、证据和分配依据时点，个性化方案另记用户约束时点。运行标识可保存在元数据里用于区分一次核验，不能据此创建平行报告或整套证据副本。

除用户另有明确要求，不生成备份文件或保留被替代的分析版本。Git仓库可承载用户自行管理的历史，但不自动提交。用户要求迁移旧档案时，将当前报告和实际支撑证据整理到上述结构，修复引用、验证后移除本次迁移范围内的冗余版本；未经迁移/清理授权，不自行删除其他历史成果。

## 历史回看与当前时间线

用户明确指定过去时点时，只用当时已公开的证据，不用今天重述值冒充当时已知值。历史回看默认在对话交付；明确要求保存独立历史成果时，使用用户指定位置或 `history/<截止日期>/report.md` 及对应 `evidence/`，同一历史成果仍就地更新，不按运行留副本。这是用户请求的独立研究对象，不是当前报告的备份。

历史任务不覆盖当前 `report.md`、state、完整研究资格或调度。普通当前研究截止不得倒退；较旧任务后完成时不应用到当前档案，也不自动归档一份过时尝试，不改截止日期绕过。相同截止时点有更正时允许直接修订唯一报告，核验受影响结论及资格即可。

## 当前报告与读取顺序

先读state，再读其指向的唯一当前报告，最后核验当前数据、证据和校验值；在修改前提取本轮所需的旧数值、核验时点及方法，供本轮差异比较，不为比较新建基线副本。报告和数据必须对应同一截止及方法，不能只读聊天记忆或状态摘要。

当前产物表只维护本轮文件及其校验值，不追加旧运行记录。报告或证据缺失、与记录哈希不符、状态未提交或写入被中断时，停止依赖该组产物的总体维持/上调/下调判断，先核验并修复一致性。不得用文件存在、最近修改时间或残留草稿推定发布成功。

## 建立与恢复基线

“有效完整基线”仅表示本轮开始时读取的报告通过[完整判据](data-contract.md#模块依赖和阻断传播)，可以作为跟踪依据，不要求独立的历史文件。主体、方法、财务与价格时点、真实依赖、评分、V/A/P、风险与催化剂必须完整；部分完成报告不获得该资格，不新增模块级基线。

无state但当前报告可靠时，核对资料、时点及完整性后可恢复状态。旧方法或原报告缺核心模块时标需重建，不继承旧总分；可复用仍有效的原始证据。无有效完整报告时，只输出有据独立事实及缺口，不假装比较性跟踪。仅请求跟踪不自动执行完整重做；用户明确补齐或完整研究时按授权推进。

## 每次跟踪必须检查

| 类别 | 最低检查内容 | 允许复用和阻断边界 |
| --- | --- | --- |
| 财报与经营 | 最新三表、附注、更正，单季同比/环比所需期间，分部与经营KPI | 确认无新披露可复用；新数据获取失败不能拿旧值当当前 |
| 价格与资本结构 | 最新收盘、停复牌、分红除权、股本、融资、回购及债务 | 除权或增发重算每股值和价格条件，调整口径一致 |
| 预测与估值 | 机构共同样本、窗口与年度滚动、分歧，当前/历史/同业指标与V模型输入 | 按真实消费方阻断；不能用旧倍数维持，也不临时改方法躲缺数 |
| 驱动与行业 | 登记驱动的最新发布、历史位置、市场边界、竞争与政策 | 无新一期要有核验依据；查询失败是未知，不是持平 |
| 风险与治理 | 期间公告、审计、问询监管、诉讼、担保、关联交易、人员与控制权 | 明确范围和结果，已证实风险即使整改也保留原发生时点与当前处置状态 |
| 假设与计划 | 每条逻辑、证伪、6—12月催化，三档A/P及损失情景、触发与分配依据；个性化约束 | 全部真实依赖通过才写未触发或维持；缺数先完成可取证的部分，不沿用旧比例 |

财报/事件从上次核验时点覆盖到本次截止；年度滚动更新十年、五年和前瞻年度，未变证据不重复下载。对话交付沿用[跟踪模板](report-templates.md#跟踪更新)的五段，篇幅控制在更新前完整报告正文的1/3以内；持久化时把受影响正文、表格、来源和缺口融入 `report.md` 原位置，保留未变且有效内容，不用五段增量覆盖掉完整正文，不另存update文件。

## 状态迁移与更新规则

- 档案状态为“待建立”“可用”“部分待核验”“需重建”“归档”；结论状态为“已复核”“待核验”“已证伪”“不适用”。可用只针对标注时点，不承诺实时监控。
- 首次资料不完整时为待建立。曾有完整报告但跟踪出现缺项时标部分待核验，保留独立事实，受影响的旧值仅作为带日期历史事实，不当作当前结论。任一评分缺项则不汇总；评分全齐而其他核心缺项可列有据筛查分，不代表完整研究已恢复。
- 补缺须重算全部受影响消费方。重大重组、口径断裂、关键重述、方法或模型失效标需重建并撤销当前完整研究资格；只有完整重做通过才恢复可用，补一个局部缺口不自动恢复。重建仍覆盖同一报告，不保留旧版副本。
- `T-`逻辑、`R-`风险、`C-`催化、`G-`缺口沿用稳定ID。已解决或失效条目记录当前状态及必要事实时点，不为保留它们复制整份旧报告。方法错误不改写成缺数，取证未完成不改写成未披露。
- 用户归档后停止自动维护；恢复、自动化增删需真实授权及工具结果，修改state不代表调度已改变。

## 写入一致性与下一次触发

使用[状态提交工具](../scripts/publish_state.py)在POSIX本地文件系统持有公司 `.state.lock`；不删除或替换锁文件，不把多文件原子替换声称为数据库事务。先在任务临时目录准备当前报告、状态和变化的数据候选，完成模板、依赖、数值及引用校验，再发布；临时草稿不是备份，成功后清理。

1. 读取当前state原始字节和SHA-256，不存在记 `absent`；载入报告及证据并记录比较依据。候选state使用带时区ISO截止时间，当前产物表填候选报告和核心数据的真实哈希。
2. 准备临时JSON映射，键为公司目录内固定相对路径（`report.md` 或 `evidence/` 下本次要更新的文件），值为对应候选文件路径。不要把 `.git`、锁或state本身放进映射。没变化的原始资料不复制。
3. 执行 `python3 <技能目录>/scripts/publish_state.py --directory <公司目录> --candidate <候选state> --artifacts <映射JSON> --expected <原SHA或absent>`。工具在同一锁内重核哈希和截止，按映射原子替换固定路径，最后替换state并回读；不生成旧版或备份。仅修订状态时可省略artifacts。
4. 哈希冲突退出3，重读最新报告/state后重新核验候选，不能只刷新expected盲重试。锁超时退出4，不抢锁；时点/时间无效退出5，不覆盖当前成果。旧state时间无时区时，仅从原证据确认等价时刻后用 `--normalize-time <ISO时间> --expected <原SHA> --directory <公司目录>` 归一化该字段，不改变研究截止。
5. 回读报告、核心数据及state，核对其哈希、截止、完整研究资格和缺口一致，才称维护完成。多文件提交中断可能有部分文件已更新；先识别实际内容，完成同一批发布或重新核验后重建一致状态，不能只按退出码假设全成功或全回滚。无需通过备份恢复旧版。响应丢失时回读候选是否已落地，不重复写入或追加记录。

工具只处理文件并发、时点及替换，不核验金融证据或模板。无法确认锁语义时不发布，说明实际限制；不以此停止其他可完成的研究。下一次触发写公司已公告日期、明确人工复核日或具体新披露事件；没有确定日期时说明窗口待定，不把法定期限冒称预约日。用户另要求自动运行时才创建并记录真实任务。
