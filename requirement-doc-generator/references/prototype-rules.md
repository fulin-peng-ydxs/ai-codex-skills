# 页面与原型规则

仅当需求涉及页面、交互或 HTML 原型时读取本文件。

## 1. 页面需求识别

- 先检查项目已有 DESIGN 文档、组件库、页面模板、布局约定、样板页面和视觉验收方式；没有时采用克制、可实现的最低交互约束。
- 判断页面属于新增页面、既有页面局部更新、复杂区域重构、工作台或可配置页面，不默认建设新的设计系统或通用平台。
- 页面需求说明入口、职责、区域关系、主次关系、操作路径、数据区、弹窗/抽屉/设置入口、关键状态、窄视口退化和页面回流。
- 页面和页面功能点引用有效需求编号，覆盖影响业务结果或用户判断的操作、反馈和状态变化。

## 2. 何时生成 HTML 原型

- 新增页面：为每个页面生成 `prototypes/{page-slug}.html`，并在需求文档对应页面条目中引用。
- 更新页面：涉及新增主要区域、布局重排、跨组件联动、复杂表单/表格/图表、工作台、配置页或难以靠文字说明的状态时生成原型。
- 文案、字段、小按钮、简单显隐、局部校验或低风险状态提示等简单更新不强制生成原型，但要在页面条目中说明原因和变更区域。
- 写入最终需求文档和必要原型前，先向用户展示输出目录、页面清单、原型清单、关键布局假设和剩余确认项；获得确认后再落文件。

## 3. 原型职责边界

- 原型只服务于需求澄清和开发理解，优先继承项目现有风格；项目无事实源时使用低保真布局，不加入营销视觉和无关动效。
- 只要求影响需求理解的关键操作、状态切换和页面回流具备演示反馈；次要控件可以静态呈现，但要明确语义和状态。
- 无法实现或暂不纳入的交互必须禁用或显著标注，不得与正式操作使用同一视觉层级。
- 原型说明、开发说明和演示控件必须与正式业务界面有明确视觉边界；演示控件文案包含“原型演示”或同等标识。
- 如支持隐藏批注，所有说明和演示控件必须随批注一起隐藏。
- 示例数据只用于表达信息结构、字段含义和状态差异，不验证生产级排序、分页、数据全集、权限实现或业务计算。
- 原型不得扩大需求范围；冲突时以需求编号和验收标准为准。

## 4. 配置化与复用

- 涉及可配置、自定义、偏好、模板或预设时，说明谁定义、谁渲染、谁保存、谁读取、谁消费、谁校验、默认值、非法值处理、失效和回退方式。
- 已有通用能力只说明页面需要消费什么及如何生效；可能新增的通用能力只描述复用诉求、适用场景和渐进接入范围，不在需求阶段指定内部实现。
- 同一能力明显服务多个页面或模块时，将其识别为基础能力，并明确样板场景、接入范围和本期不做范围。
