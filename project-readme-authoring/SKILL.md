# 项目 README 编写

## 职责与边界

参考：[文档编写规范](~/ai-agent-config/config/force/document-output.md)。

README 回答“这是什么、如何开始、常用任务怎么做、深入内容在哪里”。结构、内容与读者检查使用 [输出契约](references/output-contract.md)。

技术机制由系统架构、模块/技术专题文档维护，逐环节状态、权限与数据规则由业务闭环文档维护，交付完整性和接手风险由接手报告维护。README 保留自足使用与开发定位所需的摘要、步骤和精简目录导航；结构说明的深度按输出契约区分，不复制专题正文，也不自动生成缺少的专题。

## 输入与前置条件

确定仓库、README 路径和操作类型，读取项目规范及现有文档。首次生成或整体重构完整读取输出契约；局部更新只读取受影响要求。仅保存原文时核对基线和有效修正，不重新分析、扩写或启动命令验证，不新增验证声明。

### 命令来源与验证

首次生成、整体重构或调整运行/开发路径时，遵循有效项目规则指定的来源；未限定唯一来源时，可使用现有操作指南、脚本、构建配置及 AGENTS 引用的材料。

- 来源适用于当前项目及版本/环境，所需命令、执行目录、前提、成功判据和清理方式完整，验证证据充分且与项目规范和实现一致时，直接复用并注明来源，无需重验或另行批准。材料可组合取证，不要求先有 AGENTS。
- 内容缺失、失效、冲突或证据不足时，先查相关材料与执行证据；需要发现命令可用 [命令检测脚本](../ai-constraint-doc-authoring/scripts/detect_project_commands.py)，需要补齐执行证据或新增、修订命令时按 [验证门禁](../ai-constraint-doc-authoring/references/verification-gate.md) 执行。静态发现不证明执行成功，验证失败或无法执行按其中的“失败处理”推进。
- 来源冲突无法消解、需改变有效项目约束或修改超出授权时，说明具体差异和影响后按 [全局确认机制](~/ai-agent-config/config/force/collaboration-rule.md#需要先确认时) 请求决定；等待期间继续不受影响的内容。确需维护 AI 协作入口且已有授权时使用 [约束文档技能](../ai-constraint-doc-authoring/SKILL.md)，不因编写 README 自动补建入口。

## 执行流程

1. **核实入口事实**：读取现有 README、AGENTS、构建清单、主要源码入口及相关专题文档，核实定位、能力和目录。命令事实按第 3 步复用；源码或配置与文档冲突时说明差异，不自行编出替代命令。
2. **按读者任务组织**：读取 [输出契约](references/output-contract.md)，串联准备、首次使用、常用开发任务、结果和故障入口；核对已有专题的权威位置。
3. **取得项目命令**：按 [命令来源与验证](#命令来源与验证) 复用可靠来源或补齐证据；纯介绍、导航修订或仅保存不触发无关命令验证。
4. **写入与联动**：保留最小使用路径所需片段、执行条件及项目内来源链接，不另建平行命令定义。保留实际证据状态及获准交付限制，不把失败或未验证命令写成可用流程。标题变化时修复受影响锚点，专题变化只同步摘要和导航。
5. **检查与交付**：按输出契约走读实际使用路径，运行 `scripts/validate_readme_structure.py <README-path>`。新建和整体重构按固定模板检查；保存和局部更新保留基线，必要时使用 `--existing-structure` 做基础检查，不宣称全文模板合规。

## 核心约束

默认简体中文；代码、标识及引用原文保留项目实际写法，用户明确要求优先。README 描述当前有效能力，不把计划、历史流程或静态命令发现写成已实现、已验证。不输出密钥、私人账号或不可复用的本机路径。

## 产出边界与交付

产物为目标 `README.md`，完整生成采用输出契约的模板；保存或局部更新保留有效基线，不重排无关部分。

交付文件绝对路径、变更范围、命令来源与证据、内容校验及剩余缺口；适用时说明获准交付限制。复用既有证据不等于本次重新执行。

## 验证与完成标准

文档校验器复用同级 `skill-authoring-standard/scripts/validate_document_template.py`，其统一消费 `ai-constraint-doc-authoring/scripts/document_markdown.py`；结构从权威模板读取，不在脚本另写字段清单。安装或同步时同级提供两个依赖，缺失明确报错。

结构校验与内容验收分开：检查项目定位、适用最低内容、路径和链接，以及 README 的命令、参数、执行目录、前提和验证状态是否与权威来源一致；沿最小使用路径确认前置条件、步骤、成功结果和失败检查点能衔接。只保存时核对原文与确认状态，不把保存成功当作运行验证。
