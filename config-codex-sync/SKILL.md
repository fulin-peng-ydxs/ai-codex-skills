# Codex 配置同步

## 职责与边界

将 Codex 作为唯一来源，同步用户级技能和协作说明。使用随技能提供的 `scripts/sync_codex_config.py`，不要临时拼接复制命令。

参考：[文档编写规范](~/ai-agent-config/config/force/document-output.md)。脚本的 Markdown 围栏识别复用同级 `ai-constraint-doc-authoring/scripts/document_markdown.py`，缺失时须先恢复依赖。已批准退役项及可信历史哈希见 `references/retired-skills.json`；不能以目标现状冒充历史基线。

## 输入与前置条件

### 默认路径

- Codex：`${CODEX_HOME:-~/.codex}/skills` 与 `${CODEX_HOME:-~/.codex}/AGENTS.md`
- Claude：`${CLAUDE_CONFIG_DIR:-${CLAUDE_HOME:-~/.claude}}/skills` 与同根目录下的 `CLAUDE.md`

命令行路径参数优先于环境变量。源技能与脚本不硬编码个人路径；同步生成的目标副本使用本次解析后的绝对路径。

### 同步范围

| 请求 | 参数 | 文档处理 |
| --- | --- | --- |
| 同步全部技能与协作说明 | 默认或 `--scope all` | 同步 `AGENTS.md` 到 `CLAUDE.md` |
| 仅同步技能 | `--scope skills` | 不读取、不覆盖协作文档 |
| 仅同步协作说明 | `--scope document` | 不要求技能目录、不改技能或管理清单；不使用 `--partial`、`--delete` |
| 同步部分技能 | 隔离源、`--origin-root` 与 `--partial` | 默认仅技能；同时授权协作文档时显式增加 `--scope all` |

### 参数查询

需要完整参数时运行：

```bash
python3 scripts/sync_codex_config.py --help
```

## 执行流程

1. 明确同步目标和范围。
   - 用户指定目标或技能范围时，只处理该范围，不顺带同步其他目标、技能或协作文档。
   - 同时检查待同步技能是否引用自身安装目录、同级技能、配置根目录或目标端可执行文件；这类运行时路径必须先按目标环境适配。
   - `.system` 全部排除复制，包括 `skill-creator`。被引用的系统资源保留在稳定 Codex 来源，链接和命令改为该资源的绝对路径；同步前检查存在性，不能留下失效依赖。

2. 准备同步源。
   - 完整集合直接使用 Codex 根目录；脚本在隔离副本中把本地 Markdown 链接及 `<skills-root>`、`<本技能目录>` 运行时路径转为绝对路径，预览与执行使用同一规则，不反写源技能。
   - 脚本未覆盖的运行时路径表达须先核实并在目标专用临时源中适配，不对历史说明、工具比较、业务示例或脚本源码做无条件字符串替换。
   - 普通正文中的链接按真实引用处理；行内 Markdown 示例、非 shell 围栏（含文档模板和逐字原文）保留原文，不校验其中的示例路径。shell 围栏及普通行内命令中的运行时路径仍须转换与验证。
   - 只同步部分技能时，用隔离临时根目录承载所选技能；仅技能模式无需放入 `AGENTS.md`。相邻依赖必须在所选集合或目标已有安装中可用，不能因缺依赖擅自扩大选择。
   - 使用临时源时通过 `--origin-root <实际 Codex 根目录>` 绑定稳定来源；完整同步须与该来源的可同步技能名称集合一致。只同步部分技能必须增加 `--partial`，允许清理所选同名技能中的受管文件，不推断未选技能退役。

3. 选择模式：默认增量同步；用户明确要求删除同步、清理目标残留或镜像对齐时使用 `--delete`。只要求修改本技能时不执行实际删除。删除依据上次同步的管理清单：清理同名技能中已从源删除且目标未修改的文件，并移除源端已删除、目标未修改的受管技能。未经 Codex 管理的目标独有技能保留；首次接管仅通过明确退役记录和匹配的历史基线补齐删除依据。

   使用实际同步源先运行预览：

   ```bash
   python3 scripts/sync_codex_config.py --dry-run
   ```

   删除同步预览增加 `--delete --dry-run`；执行时使用相同源、目标及 `--delete`。

4. 检查输出中的源、目标、技能数量、协作文档状态、逐项删除清单和错误；路径适配场景还要核对临时源只包含用户指定范围，适配前后只改变目标相关运行时路径。增量同步也核对所选技能中源端已退役的受管资源，可用相同参数增加 `--delete --dry-run` 查看候选；实际清理仍按授权和基线处理。遗留执行契约未处理且无保留依据时，不报告完整对齐。
5. 用户的请求明确授权同步时，使用与预览完全相同的目标和同步源执行；删除同步须先再次核对源集合及预览清单未变化，变化时重新预览并检查后再执行：

   ```bash
   python3 scripts/sync_codex_config.py
   ```

6. 同步后检查目标文件与本次适配副本一致：普通技能路径指向目标安装目录，系统依赖指向稳定 Codex 原目录，共享规范保留真实位置，均为可用的绝对路径。系统依赖只能外部引用，目标端不得新增 `.system` 或其技能副本。
7. 按交付要求报告结果，提示重新启动或新建 Claude 会话加载新配置。

同步目标默认为 `claude`，`--target all` 作为兼容别名也仅处理 Claude。非默认安装位置使用 `--codex-root`、`--claude-root`。使用临时源时，预览与执行命令必须显式携带完全相同的 `--target` 和 `--codex-root`，不能在执行阶段退回默认全量源。

## 核心约束

### 目标端路径适配

- 需要适配的是会在目标端实际读取或执行的路径，包括技能安装根目录、同级技能引用、配置根目录和目标端命令位置；Codex、Claude 的默认根目录分别以前述“默认路径”为准，非默认位置以本次命令行参数或环境变量为准。
- 按资源归属生成绝对路径，不改变文件名、业务规则和技能语义：普通技能指向目标 `skills`，`.system` 指向稳定来源的 `skills/.system`，共享规范指向其真实位置。路径含空格时保留正确的 Markdown 与命令引用方式；源端继续使用可移植表达。
- 不得对全部文本做无条件字符串替换。用于比较不同工具、说明同步来源、展示用户输入或记录客观事实的 Codex 路径不属于运行时路径，除非它在目标端确实会被解析或执行。
- 目标专用修改只存在于隔离临时源和目标安装目录；Codex 源始终保留 Codex 自身可执行的路径。临时源必须按目标分别生成，禁止用同一份已适配副本同时覆盖不同目标。
- 预览前检查适配差异，执行后再次扫描目标技能；普通技能仍误指向 Codex、路径失效或适配超出资源归属时，视为同步未完成并修正。被明确保留的系统资源及共享规范不属于错误残留。
- 系统依赖不复制、不登记为本轮受管技能；外部引用必须指向稳定来源，不得指向临时源。资源缺失、越界或含符号链接时在写入前报错。执行共享初始化脚本时，输出目录显式指定为本次目标技能目录，不沿用系统文档中的 Codex 默认输出位置。目标运行依赖该 Codex 安装继续存在；来源迁移后须重新适配和验证。

### 同步规则

除已定义的目标路径适配外，保留源文档的结构、内容和固定契约，不在同步中重写模板；共享规范须在目标环境可读。

- 主同步集合只包含 Codex skills 根目录中含 `SKILL.md` 的一级技能目录，以及具有有效 YAML frontmatter 的一级 Markdown 技能文件；不附带复制系统技能。
- 禁止同步任何 MCP 相关技能，不区分创建、同步、审计、监控、安全或其他用途。技能目录名、技能文件名或 YAML frontmatter 中出现 `MCP`（不区分大小写）时，预览与执行均排除，并在输出中列出。
- Codex 专属技能不参与同步：`automation-management` 仅供 Codex 自动化使用，`config-codex-sync` 仅在 Codex 侧维护和执行同步。按目录/文件标识或 frontmatter 的 `name` 判定，预览与执行均列出排除项；不因其他通用技能提及 Codex 就排除。
- 忽略 skills 仓库元数据、隐藏的系统目录、编辑器目录、缓存和构建依赖；`.system` 中的资源只按上述规则核实外部引用，不参与复制。
- 目标中不存在的技能创建；已存在技能中的同名文件按 Codex 内容更新。
- 默认增量同步并更新管理清单，不执行删除。显式 `--delete` 时只删除基线匹配的受管文件或退役技能；顶层 README、未受管目录、隐藏项、仓库元数据、缓存和符号链接均保留。退役技能包含新增、修改或受保护项时整项保留并报告冲突。
- MCP 与 Codex 专属技能同时排除同步和删除，目标端已有副本保持不变。源中存在但未纳入同步集合的同名入口不能视为删除指令；空源拒绝执行。源和目标不可嵌套，目标不可重合，目标 skills 不得为符号链接。
- 删除依据完整源集合、管理清单和明确退役记录，不以文件时间或仅在源中缺失推断是否过期；不删除项目技能或源端文件。执行前预检全部目标路径冲突，删除失败如实报告已完成部分，不宣称原子回滚。
- 依赖预检使用同步和删除后的预计状态；本次生成内容引用的文件或目录若将被删除，在任何目标写入前报错，先修正引用或保留依赖。不能用删除前的存在性证明同步完成后的路径有效。
- 仅在本次范围包含协作说明时，将 Codex 的 `AGENTS.md` 同步到目标根目录的 `CLAUDE.md`，使用原子替换避免半写入。技能模式不要求该源文档存在，也不检查或覆盖目标协作文档。
- 路径类型冲突、源缺失或目标位于源内部时停止，不猜测处理，也不删除冲突目标。
- 不同步凭据、会话、日志、MCP 配置、插件缓存或其他安装文件。

### 同步管理清单与冲突

- 每个目标配置根目录使用 `.codex-skill-sync.json` 保存 `schema_version`、稳定 `origin` 和 `managed` 技能快照；快照包含路径、类型及文件 SHA-256，不保存文件正文或凭据。清单位于 skills 之外，成功执行后原子写入，预览不写入。
- 仅登记实际同步的源文件，不把目标独有文件收编为可删除基线。默认增量同步保留待删除文件/技能的旧基线，不能因本轮源端缺失就丢失其归属。
- 删除前重新核对目标快照。目标已修改、增加文件或无可信基线时保留冲突项；保留旧基线供人工处理后重试，不以当前目标内容覆盖历史基线来强行通过。
- `references/retired-skills.json` 只登记明确批准退役的名称、删除提交及可信历史版本快照。无管理清单时，只有完整匹配登记快照的目标副本可删除；未知技能不能自动退役。退役登记不是同步历史流水，后续变更按真实退役事实维护。
- 清单损坏、来源身份不一致或路径非法时在写入前停止，不自动清空清单。源目录整体为空仍停止，避免把错误路径当成全部退役。
- MCP、Codex 专属技能和完整源中仍存在但被排除的技能不因过滤而退役。部分源必须显式 `--partial`；不得省略 `--origin-root` 把临时目录当稳定来源。
- 存在冲突时继续完成无冲突项，退出码为 `2` 并逐项报告；运行错误返回 `1`，完全成功返回 `0`。不因部分完成宣称全部清理成功，不自动覆盖修改冲突或回滚已完成的同步。

## 产出边界与交付

交付每个目标新增、更新和未变化数量、协作文档结果及路径适配状态；保留未受管的目标独有技能；删除模式另报告退役项、删除清单、修改冲突、受保护残留及失败项，不因同步扩展用户指定范围。

## 验证与完成标准

核对预览与执行的源、目标、范围及参数一致；逐目标验证实际文件、引用可达性和路径归属。发现适配遗漏按流程修正，未完成不能声明同步成功。

修改同步脚本后运行 `python3 -m unittest discover -s tests -p 'test_*.py'`（工作目录为本技能目录）。路径适配须从隔离目标目录按生成命令实际运行初始化与基础校验，确认外部系统资源、普通同级依赖及带空格路径可用，并验证源文件未改、`.system` 未复制。临时样例不创建到用户正式技能集合。
