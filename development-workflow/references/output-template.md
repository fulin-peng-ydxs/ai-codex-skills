## 状态展示

任务状态及需求汇总进度使用“彩色圆点＋状态文字”，映射如下；状态含义与汇总判断沿用 [任务状态与需求汇总](../SKILL.md#任务状态与需求汇总)。

| 状态展示 | 颜色 |
| --- | --- |
| 🔵 进行中 | 蓝色 |
| 🟢 已完成 | 绿色 |
| 🟡 待开始 | 黄色 |
| 🔴 未通过 | 红色 |

`阻塞`、`跳过` 保留文字并注明原因，不套用以上颜色。颜色只辅助识别，不省略状态文字；验收项的 `待验证`、实际结果及证据仍独立记录，不转换成任务状态。仅保存原文或与状态无关的局部更新不批量改色。

## 填写与内容验收

### 固定字段的填写深度

完整目录及字段由上方固定模板维护；任务及汇总状态语义沿用技能入口。

实施范围由需求总览维护，不另设范围或增强状态表。事实、业务口径、局部风险、SQL及未决项就地支撑所属任务的方案；跨任务共用规则集中维护，消费任务引用并补差异。不得把原有各章整体搬入“共用方案”。性能、安全和兼容性始终判断适用性，低风险在对应固定字段说明依据。下表解释固定槽位的填写深度：

| 主题 | 最低内容 |
| --- | --- |
| 来源、目标与范围 | 输入文件/会话依据、目标、不做范围、项目事实及限制、输出位置；建议项沿用需求阶段状态，不能自动纳入。 |
| 技术方案 | 整体思路、关键单元的职责与选用依据、逻辑模块/运行服务/一次性任务的区分、数据流、接口、权限、兼容和取舍；按场景串联入口、处理、数据/状态、反馈与失败恢复。 |
| 需求映射 | 每项来源、范围类别、需求阶段处理状态（如有）、纳入判断、计划开发内容、任务、覆盖判断、进度及缺口。详见技能入口的映射规则。 |
| 任务与依赖 | 任务编号、输入/前置依赖、涉及文件/模块、目标、操作、产出、影响、边界/异常、验证与完成标准、状态及实际结果。状态与汇总详见技能入口，条目格式沿用上方模板。 |
| 测试与验证 | 按风险选择最低充分层级、场景、数据/负载、方法或命令、通过条件、依赖任务；执行后补实际结果与证据。 |
| SQL、发布与回滚 | 适用时说明迁移/初始化、产物进入环境的步骤、配置生效、检查、成功判据、回滚前提及方式；无此变更在对应固定字段说明。 |
| 风险、假设与未决 | 依据、影响、处理动作和确认时点；阻塞项明确关联任务，最终可执行计划不得掩盖未决阻塞。 |

总体业务说明让首次接手者在阅读任务前理解为什么做、谁从哪里开始、经过哪些关键处理或交接、以什么结果结束，以及本次改变和保持什么。简单修复用短段落说明触发与行为差异，纯技术工作说明触发方与可观察结果；复杂链路可配流程图，不强制画图。保留必要术语与业务口径，详细规则引用上游，任务编号与状态由下方总览表维护，不复制 PRD 或技术方案。

填写深度随实际决策和操作复杂度变化。简单改动可用一个任务承接实现与验证；各字段只补充本字段需要的信息，已有规则、命令和判据用具体引用连接，不在目标、方案、步骤、完成条件和发布安排反复重述整套内容。共同的不适用原因说明一次，相关字段简短引用；未启动任务的当前结果可直接写待实施，不重复罗列尚未开发、测试和发布。不得为填满字段增加独立交付任务、文档或验证层级。

### 页面、复用与配置方案

页面方案按有效项目模板覆盖适用内容，嵌入所属任务的实施方案；按共用契约引用需求行为和已有页面方案/原型，重点展开实现关系与差异。已有区域、操作路径和状态呈现不再完整重述，共用设计保留一处，不再填写通用设计模板或复制全局页面映射表。

复用治理的检索与选型依据写入所属任务的“目标与现状依据／实施方案”，消费者与迁移写入“影响与保持项／开发步骤与产出”，验证维护写入“完成条件／当前结果”。保留各候选的对应关系，不粘贴独立反馈片段的标题和字段，不新增一套复用明细。

- 逐项承接自然语言或文档中的页面功能点，以及已有原型的相关区域，建立“页面功能点/正式或本地编号 → 实现与组件/模块 → 数据/API、状态/事件、校验、权限、联动与异常 → 任务/验证”的映射。写入所属任务并关联需求总览，但不能只写“按需求实现”。未纳入项按范围规则记录，不把排除项误标为超范围开发。
- 新增或复杂页面承接页面类型、主操作/内容/辅助区、弹层/抽屉、固定与滚动归属、增长区域、窄屏和低高度退化；已有定义引用到具体区域并说明实现，不另维护布局副本。更新页面说明变更区、保留区及兼容影响。布局依据关联实际原型，或按技能入口判定无需原型时的现有页面/规范/文字方案，任务承接主要入口、数据区和加载/空/错误/权限等状态；没有上游页面方案时在此展开。
- 原型选择与专业模式前置沿用 [技能入口](../SKILL.md#产物接入)，具体格式制作与验证由原型技能维护。
- 页面方案未覆盖的关键状态和交互按性质补充：既有行为的实现细节在任务中补清，呈现缺项补入当前有效页面方案并引用，业务行为变化按共用契约更新需求来源及受影响内容；不能只在计划中形成新业务口径。
- 运行时组件先判断现有能力能否覆盖，写明共享入口、真实消费页面、状态/事件契约及验证；不足时先扩展既有能力，确需新增才拆组件产出、至少一个真实样板接入、必要清单/规范维护和验证任务，禁止套外壳后重复手写同类行为。
- 涉及布局、组件配置或页面注册时，确认项目实际机制与事实源：自动发现/继承只验证真实消费，不新增逐页登记；显式登记按本次契约补配置 schema、必要登记、存储、读取与生效；没有平台时不为表格新增体系。不适用环节说明原因即可。
- 配置、偏好、模板和预设覆盖定义/渲染、模型与默认值、权限/作用域、校验、保存、读取、实际消费、生效、重置、回退及旧值兼容。跨场景基础能力先核心模型与约束，再真实样板，最后渐进接入，明确迁移与不做范围。
- 页面方案内融合适用设计和组件/布局维护要求，不能用一张登记表代替实现。安排页面验证时读取 [前端验证规范](../../frontend-ux-audit/references/frontend-verification.md)，只计划适用场景、通过条件及任务，不在计划阶段实测尚未实现页面，也不默认跑全量 E2E。

复杂页面在任务的实施方案字段内分条展开；复用/扩展/新增判断、接入机制、必要登记及实际消费必须可辨识，不能借表格增加配置体系。

### 性能、安全及其他条件方案

性能、安全和兼容性均需作适用性判断；低风险在性能、安全与兼容字段说明依据，有实质目标/风险则在该字段逐项展开，并引用需求编号或现有约束。不应把“不适用”写成未核实的“无影响”，也不虚构默认指标。

| 条件 | 必须承接的方案信息 |
| --- | --- |
| 性能与容量 | 需求目标、现状基线/瓶颈、数据量/频率/并发/时限与统计口径；按需选择查询/索引、分页/分批/流式、缓存一致性、异步、事务范围、远程去重与超时、资源上限/释放、前端加载/渲染/请求、降级与容量方案，写明取舍、位置、任务和验证。 |
| 安全、权限与数据保护 | 保护对象、信任边界、入口/数据流及风险；按需说明认证、功能/数据权限、输入/输出、文件/富文本/外部地址、敏感信息传输/存储/展示/日志、凭据、会话/令牌、重放/幂等/限流、审计和第三方依赖；每项写明校验位置、失败默认行为、任务、正反向测试及剩余风险。 |
| 后端与第三方 | 服务与接口契约、事务、日志、异常、幂等、一致性、性能影响；第三方的超时、重试、降级、审计和联调。仅展开实际相关项。 |
| 数据库与 SQL | 字段/索引、迁移、初始化及历史兼容；按 [编码规范“写SQL时”](~/ai-agent-config/config/force/coding-standards.md#写sql时) 将适用的执行边界、重跑与恢复、前后核验安排落实到任务，文件内说明与交付信息各归其位。 |
| 发布部署 | 构建产物、目标环境、配置生效、初始化与升级的区别、前检/发布步骤/健康判据、监控与回退条件；通用流程与环境实例参数分开，未知参数标待确认，不编造可直接执行命令。 |

性能与安全实际改动必须落到任务、相应验证、必要监控/告警、上线检查、发布/回滚影响及剩余风险。缺少基线、指标或安全边界时，说明具体阻塞的方案决策、达标结论或环境操作，不能只写原则、工具名或“沿用现有机制”。实验授权、隔离边界和停止条件已明确时，可继续有界基线采集、正确性验证及参数试验；常规实验候选值标明依据与待测状态，不冒充业务指标或生产值，也不一律要求另行批准。开发环境不能完成的容量验证要写预发或上线后步骤、责任边界和回退条件；未执行验证不能算已通过。

有实质性能或安全方案时在所属任务中展开上述信息，在固定字段内分条说明；仅跨任务共同生效的约束进入共用方案。结构设计、SQL路径和迁移兼容归所属任务，跨模块执行顺序、前检和回退集中在交付安排中引用，不重复维护两份脚本契约。

### 专项工作的方案与验证

按共用契约识别工作类型，将适用信息补入技术方案、具体任务、验证及必要发布/回滚条目；复用上游契约，不复制一份专项需求表。下表是条件最低内容，不要求每次展开全部类型，也不自动执行所列操作。

| 工作类型 | 方案、任务及验证必须承接的内容 |
| --- | --- |
| 缺陷修复 | 复现条件、预期/实际与证据；区分已证实根因和待验证假设，安排定位任务及影响链路检查。回归应能检出原缺陷并验证修复及相邻边界；无法重现旧故障时说明替代证据、验证限制和剩余风险，证据不足时不得声称根因或修复已证实。 |
| 重构或升级 | 保持项与允许变化、共享入口及受影响调用方、依赖/接口/配置兼容；涉及替换时，将新旧切换、调用方及测试/门禁迁移、旧入口与失效文档清理纳入同一交付闭环；需保留旧实现时写明仍在使用的依据。以契约回归或新旧对照验证行为，说明允许差异；仅编译通过不能证明行为等价。 |
| 数据迁移、补数或修复 | 精确选择条件、源/目标及转换口径、写入顺序与并发影响；按风险安排试跑、备份/恢复，明确重跑幂等或禁止重跑的前提、长批次的断点续跑或安全重跑方式及部分失败处置。验证前后数量、关键值与业务不变量，解释预期差异并处理残差；不能只核对行数或 SQL 退出码，无法回滚时给出前向修复与停止边界。 |
| 异步或第三方链路 | 调用契约、业务完成判据及实际涉及的回调、状态迁移、持久化/查询；按机制确定超时、重试上限与停止条件、去重/幂等、乱序处理、部分成功后的补偿或人工接管。安排对应失败场景验证及必要监控；不适用机制说明依据，不凭空新增队列或补偿系统。 |
| 从零建设或技术验证 | 涉及可运行产物时明确依赖与版本/环境约束、初始化顺序、启动入口和首条可运行链路；未知选择安排有边界的验证任务。验证任务写明假设、实验输入/方法、成功/失败/停止判据及证据，结果回填结论与生产落地缺口；假设被否定也可完成验证任务，不能据此将生产实现标完成。 |

专项信息可追加到现有模板字段或就地引用；每项适用要求须关联任务与具体通过条件，实际证据仍按“任务与验证记录”填写。用户只要计划时保留待实施/待验证，不为补齐证据擅自修复、迁移或部署。

### 任务与验证记录

任务按依赖顺序排列，以可独立判断结果的业务能力为粒度；同一能力的前后端、数据与页面操作在任务内按步骤展开，必要时拆可追踪子任务。多个能力共同依赖且有独立产出的基础工作可设共享任务；不把无依赖关系的大块工作塞进同一任务。接口契约确定前不安排依赖它的联调，实现之后安排对应回归；前置测试设计可先进行。区分契约确定、实现可用与验证完成，任务依赖与验收前置不能形成完成条件循环。

#### 单个任务模板

每项任务按“目标与现状依据→实施方案→开发步骤与产出→完成条件与当前结果”展开，头部标明来源、依赖、状态及测试验证/业务验收检查点引用。现状注明可核实来源；实施方案说明复用入口、选择依据和处理关系；开发步骤承接必要测试工作，完成条件引用所需检查点及通过条件，当前结果记录实施结论并引用验证证据；风险及未决项说明影响、处理动作与解决时点。所有任务保持同一固定字段，任务总览表不能替代详细任务。

实施方案展开会改变正确性或跨任务协作的关键契约：接口的输入输出、必填/默认值与错误语义；状态的转换条件、重复或并发处理；数据的字段含义、约束、事务与历史兼容；权限的实际读写主体、允许操作、校验位置及拒绝结果。仅展开实际相关内容，已有可靠定义引用到具体位置并补本次差异，共用契约只维护一次；SQL与性能、安全等细节仍归对应字段。区分已确定的业务规则与技术选择；引入更强的一致性、全局互斥或可用性限制时，须有实际必要性和取舍依据，证据不足先安排有界验证，不将增强目标写成上游要求。常规内部编码细节留给实施，不预写全部代码或逐方法设计。

开发步骤按依赖顺序指出在什么真实入口或层次做什么修改、形成什么产出、如何判断结果或处理失败，以及何时具备供后续任务使用的条件；新增位置明确为拟新增。执行者结合任务及其直接引用应能开始工作，无须补猜关键业务或技术决定；缺少这类决定时列明缺项和阻塞范围，不用“按规范处理”掩盖。现有资料可核实的细节先调研，低风险常规选择自主处理，不因此增加确认环节。

影响范围须包括修改入口、受影响消费方、保持不变的行为和必要回归，不能用修改文件清单代替。性能、安全、兼容及SQL的独立约束保留在对应字段，开发步骤就近说明其适用影响，不重复完整契约。

已开始实施的任务记录已落地文件/模块、接口或页面行为、数据结构、权限、异常处理、验证证据，以及与计划的差异、降级、额外影响和未完成缺口；不只重复状态。生成计划前已经完成的工作按真实证据填写，不套用初始状态。

#### 验证计划与实际记录模板

测试验证与业务验收统一使用V项承载详细步骤、命令/用例范围、通过条件及实际结果。验证按风险选择编译/静态检查、领域/单元、接口/集成、页面交互、权限/数据范围、组件配置真实消费、性能容量、安全正反向、兼容回归和异常边界；不机械为每类建立空栏目。自动检查按测试目标及实际入口组织，人工验收按真实业务操作顺序组织；区分编译、测试与业务验收的结论及证据范围，不以一类通过代替未覆盖的必要验证。

每个可独立判定的检查点有稳定编号、前置、操作、预期、实际结果及证据，多个入口或边界允许分别记录结果；不能用一条长流程的单一“通过”掩盖部分失败。需求/任务关联一致的检查点在组头声明共同关联，关联不同的在对应检查点注明差异；技术检查关联所属任务及适用约束，不虚构业务需求编号。跨任务流程只写一次，每个检查点能定位受影响任务；共用账号、版本、数据与环境写一次，场景补差异，不能只留下“补测试”的汇总任务。

验证前置写清所需实现和环境何时可用：本地/隔离环境检查、部署前检查和目标版本部署后的验收分别关联相应步骤，不机械分组。检查依赖一次性动作或暂态时，写明如何建立该条件及何时采集证据，不能在动作结束或所需版本退出后才安排观察。依赖部署的验收不能反作首次部署的前置；此时先以已完成的必要前检进入受控部署，再执行目标环境验收，未通过前不标最终完成。既有流水线没有中间暂停能力时按真实阶段安排检查和失败恢复，不为计划新增未经依据的人工门禁。

V项检查点维护详细验证结果，任务维护实施结果并引用对应检查点，需求表仅同步汇总；同一检查点供多个任务引用时只维护一份结果，并核对证据对各任务的适用范围。保留证据日期及适用版本，不跨版本无依据沿用。更新时将有效修正融入当前结论，不按日期持续追加平行方案；已有详细记录只引用，未有承载处时保留必要证据，不为重构新建过程文档。

复杂检查点的步骤、命令或分支在表前正文槽位按标识展开，表内保留场景、关键通过条件、结果及详情定位；简单检查直接写表，不再复制一份步骤。多条顺序操作不压成分号串，命令使用对应语言代码块；同一判据不在正文和表格各维护一份完整定义。

计划阶段只写验证安排，实际部分保留 `待验证`，不虚构命令已执行。执行或更新时填写真实命令、用例范围和结果；非命令验证记录可复现操作步骤。失败与未执行项必须关联影响和后续动作，不以“已完成”代替证据。

涉及性能或容量改动时，在验证项的性能与容量对比字段记录：比较须使用可比环境、数据规模、负载和统计口径；条件不同应说明，不能直接声称性能改善。基线缺失须记录补测安排及其影响，实际验证后填写资源占用和未达标处置，不只记录是否通过。

页面验证承接原型或已明确页面方案的主要区域、操作与状态及响应式/低高度要求；配置验证覆盖展示、保存、读取、生效、重置、非法值与旧值；组件验证证明真实消费和正确接入机制；基础能力必须有真实样板。需求与页面功能点的验证可直接引用其验收，不再维护平行清单。

### SQL、发布与回滚模板

SQL与发布字段保留；实际涉及才填写精确操作，无相关变更在原字段说明不适用及依据。首次安装和存量升级说明各自适用路径及差异，共同步骤只写一次；仅适用一种时说明依据。未知环境参数和命令标待确认并指出补齐来源、时点及阻塞步骤，不能拿占位内容作为可执行指令；沿用来源明确的交付或核实时点，不能为减少阻塞将“交付前核实”改为“执行前再补”。条件未满足时可交付标明缺口的草案，相应最终交付项仍未完成。

仅交付源码、文档或实验结论时，在适用性说明交付对象及无部署的依据；部署专属字段简短注明不适用，不套用安装、服务健康或线上回滚流程。交付默认沿用用户指定路径、当前工作区或会话向请求者提供产物和验证结果；只有实际需要外部交接且渠道缺失时才列为未决，不为普通本地交付另索接收人或审批。

构建与发布步骤承载唯一的执行顺序，把实际需要的构建、SQL、配置、服务部署、页面产物、菜单权限及启用操作串起来，不按清单机械新增工作。可独立执行或失败的关键步骤说明目标环境/对象、前置条件、命令或操作入口、成功判据、失败后的停止或恢复位置；前置仅引用当时已可取得的资料或产物，不把本轮构建产物核验放在构建前。共同条件和判据集中说明，步骤补差异。复用已有流水线或运行手册时定位到具体入口、参数来源和本次差异，不复制整份手册，也不只写“按流程上线”。

配置与生效集中列出实际变更的位置、键、变更前后值（含新增、移除或保持默认的语义）、环境/作用域和生效方式，敏感值只写安全取值来源；发布步骤引用其执行时机，必要时明确重启、刷新、灰度或开关启用条件。SQL细节仅在所属任务维护，发布步骤引用脚本、目标库、执行时机及前后核验入口；不重复脚本正文。计划中未生成的脚本或产物标为待产出并关联任务，实际交付前核实路径、版本及适用环境，不能把计划路径当作文件已存在。

发布检查复用验收检查点，说明环境差异；每个关键步骤的结果可独立判定，失败时能知道是否继续及如何保留或恢复数据。计划阶段保持待实施/待验证，执行后将结果及证据回填已有记录，建议不等于执行授权。
