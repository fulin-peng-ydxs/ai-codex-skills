# 技能编写规范

## 职责与边界

设计和重构自有技能的流程、资源与产物契约；从参考产物创建模板技能使用 `template-creator`。

参考：[skill-creator](../.system/skill-creator/SKILL.md) · [命名](references/skill-naming.md) · [正文骨架](references/skill-template.md) · [固定模板设计与校验](references/template-validation.md) · [文档编写规范](~/ai-agent-config/config/force/document-output.md) · [测试](~/ai-agent-config/config/force/testing-standards.md)。按任务选择适用内容。

## 输入与前置条件

确定目标技能、操作类型和授权范围，读取基线及相关差异，比较相邻技能的实际能力与产物，判断新增、扩展或保持分工。局部修改只处理受影响要求；只追问无法核实且影响正确性的信息。

## 执行流程

1. **确定契约**：识别触发、排除、输入、执行分支、授权、输出、异常及验证要求。重构保留条件和例外，新建依据用户要求及有效规范。
2. **确定入口**：创建或重命名时检查标识冲突，用简洁的 `description` 表达能力和触发条件，只为易误触发场景补排除。
3. **设计产物与流程**：文档生成技能先完成唯一模板和代表性试填，再接入取证、分析、生成及检查步骤。新建或整体重构采用正文骨架。
4. **组织资源**：共用判断留正文，独立模式、完整模板及较长专项材料按需拆分；总是一起使用且无共享收益的内容不拆。初始化复用 `<skills-root>/.system/skill-creator/scripts/init_skill.py`，不重建已有技能。
5. **验证交付**：核对契约变化、引用与实际使用路径，执行适用检查，修复后复核。

## 核心约束

- 技能自身结构与业务产物分别设计；创建时的设计检查不复制成运行时审批或登记流程。
- 正文提供可执行步骤，资源补充专项内容，不退化成链接目录。
- 生成分支能找到完整模板，保存和局部更新保留已有成果；普通对话、操作和机器数据不套报告。
- 相同产物只有一个完整模板，共用语义直接引用，取证方法单独组织。无模板或未试填时不能称文档生成技能创建完成。
- 模板与命名检查器复用 `ai-constraint-doc-authoring/scripts/document_markdown.py`，不另建格式注册表；跨技能依赖须同级可用，缺失明确报错。
- 局部修改不自动改名；获准重命名时同步引用和对应副本。不修改系统技能，不顺带同步其他工具、全局路由或提交 Git。

## 产出边界与交付

在指定位置交付 `SKILL.md` 和必要资源，未指定时使用用户技能目录。不附加无用途的 README、变更日志或空目录。说明实质变化、验证及限制；文件存在不等于自动发现或跨工具同步已验证。

## 验证与完成标准

- 运行 `python3 <skills-root>/.system/skill-creator/scripts/quick_validate.py <目标技能目录>`。
- 名称、标题或 UI 元数据变化时运行 `python3 <skills-root>/skill-authoring-standard/scripts/validate_skill_names.py <目标目录>`；检查器变化运行 `python3 -m unittest discover -s <skills-root>/skill-authoring-standard/tests -p 'test_*.py'`。
- 正文用共用模板检查器校验主题、顺序及有效内容；模板按设计与校验要求检查、试填。局部修改不重排无关结构。
- 沿代表性请求走通输入、分支、结果与失败出口；检查仅审查、保存、缺失输入和相邻任务不会误触发生成、修改或外部写入。
- 重构对照基线确认每项有效契约保留、合并、迁移或有依据地删除；迁移后的要求能实际读取，不能只验证链接存在。组合模板检查重复、错位、遗漏和提示残留。
- 格式、语义和实际行为分别判断，发现问题先修复；报告实际完成的验证，不将自审称为独立审查或单次样例称为生成稳定。
