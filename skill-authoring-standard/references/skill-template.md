# 技能正文默认骨架

本文件唯一维护自有技能正文的默认结构与填写提示；设计流程、资源选择和验证由 [SKILL.md](../SKILL.md) 维护。创建或获准整体重构时使用，局部修改沿用原结构。以下提示指导编写，不原样复制到交付技能。

## 默认模板

以下正文采用默认骨架。职责、执行、交付和完成判断须可辨识；输入或专项约束没有独立内容时并入相关章节，不保留空章；多模式流程可在执行部分展开，不拆散共享前提。YAML 文件契约由系统 `skill-creator` 维护。

名称按 [命名规范](skill-naming.md) 填写。

```markdown
---
name: skill-name
description: 描述具体能力、触发场景，以及容易误触发时的必要边界。
---

# 技能中文名称

## 职责与边界
说明技能负责哪些工作、不负责哪些工作，以及与相邻技能的分工。
说明本文件与相关资源各维护什么，复用本章节承载文档边界。

## 输入与前置条件
说明实际需要的信息、优先获取来源，以及信息缺失时可继续或必须等待的条件。

## 执行流程
按“输入 → 条件分支 → 动作 → 结果/失败出口”的实际顺序填写。
规则给出可匹配条件，操作给出命令/入口和结果判据；不要只列阶段名称或抽象原则。
引用专项资源时说明何时读取，不要求所有任务加载全部资源。

## 核心约束
仅写影响本任务决策的专项规则；通用规则引用权威入口。

## 产出边界与交付
明确交付物包含什么、排除哪些易混入的内容。
说明返回方式、何时落盘、保存位置，以及适用的最低内容或固定字段；不自动生成相邻技能负责的产物。
生成文档时，在此内联产物要求或指向其权威资源，按实际执行分支说明读取条件；具体设计标准由技能编写规范维护，不将设计检查抄入目标技能。

## 验证与完成标准
用代表性输入确认能查到下一动作并取得可观察结果；列明适用检查、证据和失败/未验证处理，不能仅以章节齐全为完成。
```

## 裁剪示例

- 简单转换技能：输入可并入执行流程，格式限制并入产出边界与交付；产出边界也可与职责边界合并，仍需明确支持的转换范围、交付范围、失败条件和结果检查。
- 多模式分析技能：共享主题保留在入口，在流程中按输入选择专项参考文件，不将各模式全文复制到入口。
- 局部修订现有技能：只维护受影响内容，不要求将旧标题改名为模板标题。

示例说明组织选择，不规定所有技能的业务步骤、交付物或验证命令。
