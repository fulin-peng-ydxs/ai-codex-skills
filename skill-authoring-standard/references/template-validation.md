# 固定模板设计与校验

适用于自有文档生成技能的正式产物模板设计、使用与检查。相关入口：[技能编写规范](../SKILL.md)。

## 模板设计

- 每类正式产物使用一个完整模板，明确用途、章节、字段、顺序、表格、重复单元和条件分支；目录不能代替可填写的完整骨架。
- 各章及字段明确必答问题、最低信息、解释深度、证据和充分性判据；共享语义引用已有来源，不重复定义。
- 条件规则区分适用、不适用、无记录和未知，说明缺失输入的处理。重复对象使用同一结构，稳定编号不随排序重编，不用总览替代详情。
- 填写说明与交付骨架分开，说明和工具本机路径不得泄漏到产物。嵌入片段使用父模板结构。

## 生成约束

- 首次生成或整体重构按完整模板填写；标题、字段、表格及其位置和顺序固定，不因篇幅或输入长短临时增删、改名、合章或换形式。
- 仅填内容槽位、增减声明的重复单元或执行明确的条件分支。字段标签用于定位内容，不限制为一句话；原因、机制及取舍在字段内用连贯段落，顺序操作用编号步骤，按下方语法续写。不要把占位提示逐词改成短句，或把完整说明塞进一个表格单元。正文槽位可用段落、列表、表格、代码和图，但不自行新增标题或固定字段；结构不足时维护模板。
- 条件章节默认保留，不适用或无记录说明原因，未知说明缺项和影响；不造空条目，也不用示例补事实。
- 用户指定格式和有效项目契约优先；摘要或提纲按用户请求及技能已有模式交付。缺少所需模板时报告缺口，不把自行组织的正文称为模板合规。
- 保存和局部更新保留基线，只检查受影响要求；完整正文在对话交付时同样检查，可用临时文件，不新增长期产物。

## 设计验证

- 用简单、复杂、条件不适用和输入缺失的代表性案例试填，适用时覆盖保存和局部更新；核对完整正文、证据及未知项，从读者角度确认能否理解原因、沿步骤操作、按条件判断及找到失败出口。检查长表格单元、字段短句和重复规则是否妨碍查用；必要摘要与具体判据保留，不以字数、段落数或表格占比设门槛，也不为增加正文重复已有内容。
- 共用检查器从模板读取结构，不另维护字段清单。维护缺章、错序、缺字段、非法新增、空值及占位残留等反例，并确认合法内容能通过。
- 模板变化同步消费者和相关测试；检查未通过先修复，不为通过而放宽规则。多轮生成稳定性须实际评估，单次试填不足以证明。

## 模板语法

权威产物资源用一个 `document-template` 代码块承载完整骨架；同一技能确有不同产物时可用块名区分（例如 `document-template agents` 和 `document-template claude`），不是同一产物的自由变体。外层用四个反引号可容纳内部示例代码块。

- `{{@内容提示}}` 是唯一的变量占位；标题中的占位只替换对象名称/编号，固定部分保持。普通 `{id}`、`{colors.primary}`、JSON 对象及 `{{user.name}}` 属于正文或业务语法，不作为模板占位符。模板与示例统一使用显式前缀，不混用旧的单花括号提示。
- 标题末尾 `<!-- repeat -->` 表示该完整条目可重复零至多次；`<!-- repeat-required -->` 表示至少一次。标记只用于模板，生成时移除。不输出无事实对象的虚构条目；零次在父章节写 `条目情况：无：原因` 或 `条目情况：不适用：原因`。
- 普通标题只能出现一次，层级和顺序固定；条目内部所有标题和字段同样固定。
- 标题末尾 `<!-- flexible-body -->` 用于技能自身的正文模板，声明章内可自由组织；该章只放一个自由文本占位，不与固定子标题、字段、表格或重复条目标记混用。成品移除标记，可在该章内使用有用途的子标题、段落、列表、表格和代码，仍检查层级连续、同级标题唯一、叶章节有内容、表格列齐全及标记残留，外围主题及顺序照常检查。此语法不授权正式产物开放结构或豁免必填字段；正式产物使用各自固定模板，结构变化回到模板维护任务处理。
- 单独一行的 `- 字段名：{{@内容提示}}` 或 `字段名：{{@内容提示}}` 声明固定字段，支持 `：` 与 `:` 两种分隔符，保持顺序和列表/普通文本形式。字段值可以是行内文字，也可以完全由其后的多行内容组成；多行表格、图示、代码或列表使用至少两个空格续写缩进以归属该字段，空行不结束归属，下一非缩进内容或固定字段结束归属。纯空白、后续另一字段或未闭合围栏不能充当本字段的有效值。在固定字段区域，列首的“名称：内容”按字段检查，未声明字段不能靠去掉列表标记或加粗绕过；含冒号的补充及嵌套条目缩进后作为字段内容。模板另有独立正文槽位时，仅在其边界内将含冒号的段落、条目标识和编号步骤视为正文；已有固定字段仍检查位置、顺序及非空，不能被正文吞掉。缺失字段不能通过缩进规避，仍会报缺项。首个标题前的 YAML 元数据由产物专用检查器负责，技能元数据仍使用系统 `quick_validate.py`。
- 模板显式声明的表格保持表头、列数和位置，数据行不得留空单元格。模板数据行首列没有占位符时，该值是固定行标识，必须唯一、完整且依原顺序出现，不能用空集合说明省略；首列含占位符时，该行是原位置可重复零至多次的行原型。每行保留模板各单元格中的固定文字，只填变量；动态行不得占用同表固定行标识。仅有表头的模板允许填写任意非空数据行。
- 空表保留表头及分隔线，在分隔线后的首个非空行、与该表相同缩进处写 `条目情况：无：原因` 或 `条目情况：不适用：原因`，可用列表形式。该说明仅绑定紧邻的前一张空表，不能放行同节其他表或替代独立重复单元的空集合说明；“适用性”字段、引用、代码或其他位置的说明不能代替该表的说明。条目情况不属于任意新增字段；说明内容是否真实、是否确实允许无记录仍须按所属模板做语义核查。
- 无字段标签、独立成行的占位是正文槽位，可以在前后固定字段、表格、代码或字面边界之间放必要段落、列表、表格、图和代码，不改变标题结构。固定字段的值槽位同样允许这些内容，按续写缩进识别；模板明确为按需补充的正文槽位在条件不成立时可不输出，不填“无补充”占位。标题、表格单元格和代码内的占位仍保持各自承载格式。这与 `flexible-body` 不同，不授权新增子标题或固定字段。相邻的独立表格使用空行分隔，避免被解析成同一张表。
- 槽位内自选表格只检查自身列数、非空及空表说明，不要求与模板表头一致；显式声明的表格仍逐项匹配，不得将其移入另一字段或原文块抵消缺失。没有字段或固定文字边界分隔时，与相邻固定表头相同的表格仍按固定结构匹配，不当作自由内容吞掉；固定代码的语言标识和数量同样保留。确需在不同位置使用同表头或同语言代码时，以模板已有字段或固定文字界定边界，不增加成品隐藏标记。
- 固定模板及完整交付文档中的代码围栏必须显式闭合，避免后续章节或未填标记被吞入代码。保存原文仍遵守基线保留边界；原文含围栏时使用足够长的外层围栏承载。
- 普通代码同样检查非空、显式占位和模板标记。树结构、正文、围栏和代码归属统一消费共用解析器的字段续写视图：在字段的两个空格续写容器内，按相对零至三个空格识别围栏，所以字段内四空格缩进的围栏同样检查闭合；解析保留原始行和位置，不改写原文。未进入字段的普通Markdown仍按全文缩进识别。反引号、波浪号及嵌套包装沿同一入口检查，代码中的 TODO 或业务花括号不因此成为未填槽位。全部代码块均参与归属匹配，与模板是否声明固定代码块无关；槽位外代码不能作为额外内容通过。槽位内图示/代码与模板明示的代码分开识别，不改变后者的语言标识、数量或原文豁免；检查器不验证命令执行结果或Mermaid图的关系语义。
- 模板用 `text verbatim` 围栏且内部只有一个占位符时，声明逐字原文槽位；成品去掉 `verbatim`，保留普通文本围栏及真实原文。只有与权威模板对应的原文块可保留原文自带的占位语法或示例标记，不能在成品自行声明豁免；整个原文块仍是原模板占位符时报告未填。来源、哈希及内容完整性另外核对。

## 命令

从任意目录调用，技能根使用实际安装位置：

```bash
python3 <skills-root>/skill-authoring-standard/scripts/validate_document_template.py --template <权威模板路径> --check-template
python3 <skills-root>/skill-authoring-standard/scripts/validate_document_template.py <产物路径> --template <权威模板路径>
```

多个产物块时增加 `--block <块名>`。模板自身的目录和字段不在检查器另写一份；外部格式明确优先时传实际权威模板。保存原文和旧文档局部更新只核对基线、受影响内容及既有检查，不用新模板校验强迫全文迁移。

## 验证边界

检查模板及产物的同级标题唯一性、标题层级/顺序、重复单元、字段顺序及非空、表格列及空值、固定行标识/顺序和行原型、显式占位和标记泄漏；出现未闭合的 `{{@` 也算残留。原文豁免仅按上方声明的槽位处理，不把业务语法当作文档字段。字段内容是否真实、判断是否充分、业务状态是否正确及实际运行结果仍须取证和语义走读；未知说明不是模板未填写，明确记录具体缺项及影响即可。不要把格式 PASS 表述为内容或运行验收通过。

检查器不判断章节是否有用、事实是否可靠或引用是否必要，这些内容须结合实际产物核查。

修改检查器后运行：

```bash
python3 -m unittest discover -s <skills-root>/skill-authoring-standard/tests -p 'test_*.py'
```
