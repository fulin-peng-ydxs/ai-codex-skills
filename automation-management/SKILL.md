# 自动化任务管理

## 职责与边界

管理 Codex 自动化配置、提示词和运行故障。配置字段与操作以当前 `automation_update` 工具 schema 为准；业务规则由调用的技能及项目规范维护。

参考：[文档编写规范](~/ai-agent-config/config/force/document-output.md)。自动化需要文档产物时引用对应业务技能的输出契约。

## 输入与前置条件

发现当前可用的自动化工具，读取已有配置，确定创建、更新或诊断目标。已有同目标任务优先更新，避免重复。只补充无法从会话及配置获得的目标、频率/时区、对象、所需能力和汇报/失败要求。

定位已有任务时查看 `${CODEX_HOME:-$HOME/.codex}/automations/*/automation.toml`；已知 ID 用工具 `mode: view` 读取。诊断仅使用实际存在的记录和字段，不假设各版本日志布局一致。中文会话优先使用中文任务名称、提示词和汇报。

## 执行流程

### 创建或更新

1. **选择类型**：周期跟进默认当前聊天的 `heartbeat`；仅用户明确要求每次新建独立任务或独立项目作业时使用 `cron`，从项目列表取得单个 `projectId`。独立多仓作业每个 cron 绑定一个项目，检查重复运行与并发提交风险，不构造不支持的多个 cwd 字段。
2. **预检查**：核实目标路径及实际需要的技能、脚本、配置、凭据来源；Git 任务核对仓库和工作区。识别文件、网络、消息、推送、写库等动作的授权及当前工具能力，不输出凭据值。
3. **保存配置**：按下述提示词规则调用 `automation_update`。更新传入既有 ID 和完整更新字段，保留未要求改变的配置；命令授权依赖精确匹配时使用稳定显式命令，如 `git -C <仓库绝对路径> push`。
4. **核对结果**：回读配置，执行安全预检查。实际试运行会推送、发送消息、写库、调用外部 API 或长时间执行时，先核对该动作的已有授权和工具能力。授权与能力允许时运行一次关键链路并核对自动化自身记录；失败后按“诊断与修复”处理，无法运行则保留未验证状态。

### 诊断与修复

1. **取证**：读取配置及实际存在的 `automations/<id>/memory.md`；证据不足时在 Codex 根目录实际存在的 `logs_2.sqlite` 中按 ID、名称、路径和错误查找，再按需读取 `log/codex-tui.log`。缺少日志时说明证据缺口，不将其视为未执行证明。
2. **定位原因**：区分调度/项目绑定、文件系统或沙箱、仓库状态、DNS/网络、远端凭据、缺少依赖、命令未命中授权，以及重复运行造成的锁竞争。当前聊天成功不能证明后台成功，DNS 错误不能单独证明沙箱限制。
3. **处理**：只诊断时给原因和建议；已要求修复时，在授权内调整提示词、项目绑定或配置。权限重试和持久规则按下方边界执行，需要用户凭据或 App 设置时说明具体阻塞。
4. **复验**：能力与授权允许时重新运行自动化并检查实际结果。无可用运行入口时，分别报告配置与本地预检查证据，不以同名命令成功替代后台验证。

## 核心约束

### 提示词职责边界

提示词须能独立执行，包含固定目标、成功与失败判据、资源入口、特有差异、授权/排除范围及结果交付位置。依赖技能用短句要求读取并遵守，业务细则、模板、项目规则和测试矩阵不复制，不将模板固定字段改成可选；只重复必要的安全红线、外部副作用及机器读取契约。不要写大段历史、创建原因或临时解释。

持续监测默认无变化或无可行动事项时保持安静，仅在有意义的变化、完成、失败或需要用户处理时通知；用户要求周期汇报则遵从。通知静音用工具 `notificationPolicy=failed_runs_only`，取消静音用 `null`，不写入任务提示词。

### 网络与权限

- 不自行替换为系统 `launchd`、`cron` 等调度，除非用户明确要求换方案。
- 基于后台日志判断故障后，只在工具支持、环境允许且授权适用时重试同一精确命令；禁止升级或能力缺失时报告阻塞，不绕过权限。
- 持久权限变更须明确授权并通过受支持配置入口，限定必要的精确命令；不默认改写 `default.rules` 或添加宽泛 `git` / `git push` 规则。
- 创建或更新任务不自动授权发消息、推送或写库；已有有效授权直接复用，只有新增范围需要决定。

## 产出边界与交付

交付名称、实际配置变更、运行状态、验证证据与阻塞项；仅诊断不改调度、权限或提示词。Git 目录监测可按需参考 [配置示例](references/git-directory-monitor.md)，不将其时间、范围和推送授权套用于其他任务。

## 验证与完成标准

分别核对配置保存、安全预检查及自动化自身运行结果。实际运行后检查日志、输出与必要副作用是否符合目标，失败如实报告；只有本地命令或配置证据时不称后台完整链路通过。
