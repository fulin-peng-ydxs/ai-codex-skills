# Git 目录监测示例

本文是 Git 目录监测的配置示例；调度选择、诊断、授权与验证规则由 [技能正文](../SKILL.md) 维护，Git 范围、暂存、提交和推送复用 [git-push](../../git-push/SKILL.md)，该技能再调用提交消息技能。示例不构成提交或推送授权。

## 输入与适用条件

以每天 23:00 监测用户指定技能仓库为例。先确定仓库绝对路径、时区、可提交范围，以及是否允许自动 commit 和 push。只有用户明确要求提交全部 Git 可见新增、修改、删除时才使用 `git add -A`，排除 `.gitignore` 文件及禁止提交的内容；否则按授权文件范围暂存。

默认使用当前线程 heartbeat。用户明确要求独立项目作业时，调用项目列表取得对应 projectId，每个 cron 绑定一个项目；不配置多个 cwd，也不重复创建同目标任务。

## 预检查与提示词

检查仓库根目录、`git status --porcelain --untracked-files=all`、已有暂存内容、Git 提交推送技能及其消息技能依赖的实际路径、Git 身份和远端配置。已授权推送时，还须核对目标分支、上游及待推送提交；准备推送时更新必要的远端证据，上游缺失或远端不可达不能判为没有待办。下面是已经获准自动提交并推送时的提示词骨架；将占位符替换成已核实的实际入口：

```text
每天检查 <仓库绝对路径> 的授权文件范围 <范围>，忽略 Git 排除的文件，不处理其他仓库。
分别检查授权范围内的未提交变化和目标分支待推送提交。有待办时读取并遵守 <git-push/SKILL.md 的实际路径>，本轮变化按范围提交；此前已提交但尚未成功推送的成果核实后继续推送，不创建重复或空提交。
推送前核对实际会发送的全部提交是否均被授权覆盖；混入未授权或归属不明的提交时停止推送并报告，不因其中包含本任务提交就整批放行。
这是自动化流程内部调用，沿用非显式交互模式，不重复询问已获授权的范围和动作；范围无法安全确定或依赖缺失时停止并报告阻塞，不扩展授权。
报告有意义的变化、提交 hash、推送结果或需要处理的阻塞；提交成功但推送失败须分别说明，避免重试时重复提交。
没有待办且没有需要处理的异常时保持安静；已报告且状态未变的阻塞不重复通知。
```

只授权本地提交时，删除待推送检查、推送续跑及推送授权核对要求，明确“仅本地提交，不推送”；工作区干净即可判定本地提交无待办。通知静音设置通过工具字段处理，不混入提示词。Git 执行和消息格式由依赖技能维护，提示词只补自动化特有目标、范围、授权及汇报要求。

## 验证与失败诊断

- 在授权与工具能力允许时运行自动化本身，检查运行记录或实际存在的 memory.md，确认没有重复运行、锁竞争，并分别核实 commit 和 push。当前聊天命令成功不能证明后台成功。
- 工作区无变化时，已授权推送的任务仍核对待推送提交及既有失败；仅本地提交的任务不因分支领先远端产生推送待办。未提交时检查范围、身份、hooks、写权限和已有锁的持有进程，不直接删除锁。
- 已提交但推送失败时，区分 DNS、网络、沙箱、凭据和远端问题，不把所有失败都归结为缺少网络授权。
- 权限升级、持久规则和替代调度遵循正文及当前环境限制；禁止升级时报告阻塞。不能实际运行自动化时明确尚未完成后台链路验证。
