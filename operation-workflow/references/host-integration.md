# 运维宿主接入与命令确认

本文供首次接入、宿主或执行通道变更、接入维护及命令确认衔接时读取，维护Hook注册、答复核验、通道验证与覆盖限制。命令配置及分类语义由[命令策略](command-policy.md)维护，授权触发与批准范围由[主流程](../SKILL.md#审批判定)维护，执行证据由[记录契约](records.md)维护。

## 适配与命令确认

[hook_command.py](../scripts/hook_command.py)适配调用前事件：宿主PreToolUse → 原check_command.py识别本地校验或SSH入口 → 精确SSH目标的远端命令分类 → 当次命令确认或继续/停止。它不执行候选命令，不维护第二套权限表，不创建方案快照、批准编号、批准数据库或独立审批界面。任务范围批准与命令确认的分工统一消费[主流程的审批判定](../SKILL.md#审批判定)。

先按[判定结果与下一动作](command-policy.md#判定结果与下一动作)区分普通ask与停止分支；下表的ask仅指可进入当次命令确认的普通ask。非普通ask由适配器转换为stop，人工答复不能解除。平台执行权限按主流程独立核对。

| 宿主 | allow | 普通ask | deny/异常 |
| --- | --- | --- | --- |
| Claude Code | 不追加许可 | 返回`permissionDecision=ask`，由宿主取得答复 | 阻止 |
| Codex | 继续 | 暂停，由AI问询；重试时核验真实答复，单次放行 | 退出2阻止 |

Claude的ask响应使用PreToolUse事件。各宿主自身的执行权限检查继续生效。

原生ask和AI问询是两种确认衔接方式，不能因Hook不支持直接ask就把方案改成命令清单。Codex问询桥接只解决项目命令策略的人工决定；例如平台执行权限为never时，仍不能申请沙箱提权，但可以在已有平台权限内确认任务操作。不能改变宿主权限来制造弹窗。

### Codex当次命令确认

1. Hook暂停候选命令并返回结构化问题，问题绑定本次完整命令、目标身份和策略版本。
2. AI先说明用途和影响，再使用`request_user_input_async`展示这一个问题并等待答复。问题标题、命令、目标、策略版本和两个动作保持原文；选项显示顺序可调整，不能替换或增加动作。问询工具不可用或用途受限时，说明原因，在最终消息原样展示问题标题，空一行附`请回复“执行本次命令”或“取消”。`，等待真实用户答复。
3. 用户选择“执行本次命令”后，AI重试未改动的原命令。Hook核对当前原生会话、项目、答复所属turn、真实用户消息及其对应问询，匹配后允许一次；降级为对话问询时仍核对宿主保存的问答。
4. 取消或拒绝不重试；未回答不执行。不接受旧方案批准、AI写入的approved字段、其他会话或改动后的命令作为本次答复。

一次批准后只执行一次；若为测试重复答复核销而再次触发ask，不再把同一测试问题反复发给用户。问题由Hook生成，但问询展示由AI完成；整体方案、结果确认和归档步骤仍由技能驱动，不宣称Hook自动执行整个任务流程。

### 答复核验与核销

核验只读宿主`thread/read`与`thread/items/list`，不恢复或启动模型任务，不同步回执到文档。答复ID的存储只防重复使用，不能创建授权：

- `.local/operation-hook-used/`按会话追加已核销答复ID，持锁检查已有记录后追加并落盘；后续答复不覆盖旧ID，旧式单ID文件按一条记录保留。
- 单文件上限2,000,000字节，达到上限或无法读写时停止，不自动截断、轮转或删除旧记录。
- 答复查询失败保持暂停；执行结果未知不自动重试，重新执行须重新确认。

## 配置预览与注册

配置预览在启用前或下述技能维护入口运行，只输出到stdout，不覆盖设置、改变沙箱或自行信任Hook：

```bash
<已核验Python绝对路径> <技能目录>/scripts/hook_command.py \
  --host codex \
  --project-root <项目绝对路径> \
  --print-config
```

按当前宿主选择`--host`及合并位置，只注册调用前判定，不注册方案批准监听：

- `codex`：项目`.codex/hooks.json`。
- `claude`：项目`.claude/settings.json`。

Codex问询桥接依赖已安装CLI和可读的原生会话历史；缺少有效session_id/turn_id或宿主不保留所需历史时暂停并报告，不能扩大批准范围。启用时完成宿主要求的原生审阅/信任，并以实际安全探针确认拦截；配置存在、enabled或trusted标签均不能代替运行证据。

## 初始化接入步骤

新项目初始化必须在首次服务器操作前完成下列接入；首次换宿主、注册入口或执行通道变化时只复核受影响部分，不能把CLI的验证结果直接沿用到桌面或其他通道。

1. **确定宿主和绑定**

   从当前运行环境确认宿主及执行通道，不凭已安装某个CLI猜测。核对项目绝对路径、实际OPS_ROOT、Python 3.11+与PyYAML，以及上表所需的确认能力；Codex另核对本机CLI及原生会话历史可读性。

   资料或能力不明先核实，不安装无关软件或顺带配置其他宿主。

2. **启用前隔离自检**

   在写入可能立即生效的Hook配置前，复用现有生成器及tests/隔离输入检查配置可解析、项目/运维根绑定、allow/ask/deny、取消/拒绝、重复答复、伪造回执、显示顺序及异常响应。命令只作为文本传给适配器；需验证子进程时只运行本地假SSH，不连接真实服务器。同步验证下方本地校验入口的合法、越界及未知脚本分支。

   准备并核对后续本地假SSH探针，其代码只能写本地标记，不得联网或执行传入的命令。自检失败先修复，不启用；已有Hook时使用下述维护入口，不临时停用现有保护来跑自检。

3. **生成并落地配置**

   由AI负责读取、合并并保存配置，不只交付生成命令。复用已自检的`--print-config`输出，将host替换为当前宿主；自定义OPS_ROOT追加`--operations-root <项目相对路径>`。目标配置缺失时创建必要文件。

   以适配器入口、宿主及project-root识别本技能已有注册，相同内容不重复追加，变化时仅更新对应条目。保留其他Hook、事件、权限和设置。

   JSON损坏或归属冲突先停止修改并核实，不覆盖整个文件，不为让验证通过而删除或放宽其他规则。

   将本地临时探针和使用标记所在`.local/`纳入Git忽略，保留原忽略规则。配置只引用共享适配器和项目策略，不复制权限表。

4. **完成宿主启用**

   核对实际加载位置和启用状态，仅宿主要求的人工作业由用户完成。宿主要求人工审阅/信任时，先完成配置及差异展示，再请用户通过其原生入口完成；已有效且未变化的信任直接复用，不自写信任状态或绕过审阅。

   仅需本地骨架、尚无服务器资料时可完成配置准备，保持待验证，不虚构接入成功。

5. **验证当前通道**

   启用后只通过当前宿主执行预先准备的本地安全探针，验证自动触发而非AI手动调用脚本；使用假SSH的绝对路径，不调用系统SSH或真实服务器操作。

   首次或缺少同通道有效证据时，最小实测allow继续、deny阻止及一次ask真实确认后的单次放行；随后验证旧答复不能再次放行，出现测试ask即停止，不重复提问。取消/拒绝及伪造回执等完整分支由隔离测试验证，不要求用户依次配合人工拒绝。日常收到取消就不重试；仅观察到AI未重试时，不写成Hook拒绝回执已实测。当前策略缺少用例时用隔离样例，不修改实际权限凑测试。

   人工问询前明确本地接入测试及其不联网的作用，单次说明测试范围；不混入业务排障的逐命令授权。当前通道已有有效证据、注册和原生回执接口未变时，只补本次影响的隔离测试和本地检查器实测，不重做人工问询。代码单测不能冒充首次真实宿主实测，隔离通过和实际通道证据分别记录；临时文件按全局规范放置并清理。

6. **记录状态并继续**

   在项目AGENTS既有工具/验证条目记当前宿主、入口、验证通道与覆盖范围；明细只关联本次execution.md。按实际验证结果记录状态：

   - 当前通道所需分支通过：已验证。
   - 配置已写、尚待信任、仅模拟或部分验证：待验证。
   - 宿主无Hook或适配器缺少必要确认能力：不支持完整接入，并说明具体缺口。

   待验证或不支持完整接入时，继续本地准备，暂停首次服务器操作；不自动退回仅靠AI主动判定，也不新建接入报告、状态JSON或批准文件。

后续维护时，配置查看与局部更新使用宿主文件工具；本地生成器、隔离测试和校验走下方受控入口，核对实际project-root、operations-root及平台权限。该入口只做本地维护，不执行服务器动作；不能只改工具workdir冒充更换原生会话，也不得关闭Hook或搬移服务器命令规避检查。更新注册后按需重新审阅并补受影响验证；无法使用合法入口时报告准确缺项及恢复步骤。

## 受控本地校验入口

由check_command.py的classify_local统一识别，Hook不另列权限表。Python使用当前Hook注册所用解释器的绝对路径，避免Hook与工具进程PATH不同；裸python3、解释器-c、任意脚本、未知参数及shell组合不在此入口内。输入须是有界普通文件或实际目录，无路径逃逸；已安装代码是信任前提，此机制不是Python沙箱。

| 工具 | 允许的用途与范围 |
| --- | --- |
| skill-authoring-standard/scripts/validate_document_template.py | 检查当前项目或正式安装技能内的Markdown；模板限正式技能references/；支持--template、--block和--check-template，不执行文档代码 |
| operation-workflow/scripts/check_archive.py | 仅index子命令，--repo精确绑定当前项目、--operations-root绑定注册运维根；只检查真实Git索引，不暂存、不提交 |
| operation-workflow/scripts/check_command.py | 只分类当前运维根command-policy.json中的候选命令文本，不执行候选命令 |
| operation-workflow/scripts/hook_command.py | 仅当前Codex项目的--print-config预览，不运行候选命令或更改注册 |
| .system/skill-creator/scripts/quick_validate.py | 只检查已安装技能目录 |
| Python -m unittest discover | 仅当前operation-workflow/tests/内的隔离回归，测试模式限test*.py，无真实服务器连接 |

这些本地检查不借用服务器白名单或远端allow；没有服务器登记也可做本地准备。未知脚本仍停止。准备阶段先以此入口核对必需校验器；检查失败要修复输入或入口，不能把“检查器未运行”记为文档检查不通过或通过。

## 覆盖与失败边界

### 项目与目录绑定

依赖Python 3.11+与PyYAML。适配器按以下边界定位项目和目标：

- 固定project-root限定所属项目，工具cwd与原生会话cwd共用规范路径的归属判断。原生会话允许项目根及子目录，项目外或软链接逃逸时拒绝答复核验。
- 项目外的工具调用不继承本项目许可，交回宿主自身权限。
- operations-root默认为`agent-works/operations`；自定义时须为项目内相对目录，拒绝绝对路径、上级跳转及软链接逃逸。
- 从该目录的服务器清单与项目策略绑定精确地址、端口和账号。

### SSH传输要求

当前支持的入口为非交互SSH，须同时满足：

- 显式`-F /dev/null`。
- 严格主机核验，禁连接复用。
- 末尾只有一个远端命令参数。

未知选项、代理、转发、脚本、解释器及组合语法停止，不猜测内层动作。连接策略中的语义禁止项、主机指纹及凭据核验仍由执行者先检查。

### 未覆盖路径与失败限制

普通本地命令仍服从宿主原权限；任意可执行程序、文件工具、SQL/API及持续write_stdin输入未形成完整覆盖。不提供同账号防篡改或系统级隔离。脚本捕获的错误统一阻止，但宿主对脚本启动失败、超时或未覆盖路径可能继续执行；因此必须分别验证适配器和真实宿主。

协议与限制见[Codex Hooks](https://learn.chatgpt.com/docs/hooks)、[Claude Hooks](https://code.claude.com/docs/en/hooks)。验收按上述初始化接入步骤执行；模拟事件不能冒充真实客户端验收。Windows/PowerShell不属于当前支持的命令入口。
