# 运维文档固定模板

本文唯一维护该产物的固定结构、字段、条件槽位和内容验收；执行流程、授权与保存由 [技能入口](../SKILL.md) 维护。生成或整体重构前读取 [文档输出规范](~/ai-agent-config/config/force/document-output.md) 与 [文档边界规范](~/ai-agent-config/config/force/document-boundaries.md)，更新和保存遵循其保留边界。

## 生成说明

使用下方完整模板填充；标记语法及校验命令见 [共用模板检查用法](../../skill-authoring-standard/references/template-validation.md)。本产物的具体填写要求见模板后的内容验收，通用生成与更新边界沿用上述全局规范。

## 填写与内容验收

各块对应不同实际产物，不自动全建。接入、盘点、变更、汇报和记录的触发与授权仍由主流程维护，目录见 [工作空间](workspace.md)，历史证据与纳管见 [留痕](records.md)。内容呈现统一消费全局输出规范，下表只补运维信息的归属和最低判据，不建立另一套排版规则。

### 各产物的信息落点

| 产物与落点 | 运维专属信息及验收 |
| --- | --- |
| access：身份、连接与撤销字段 | 能区分资产身份、登录账号、运行账号和提权边界；主机密钥的本地记录与可信确认分开。连接参数可定位到完整持久来源；授权必须对应真实来源、范围及失效条件，不能把历史批准转成长期许可 |
| index：导航表及跨服务字段 | 每个实际单位有稳定ID及详情入口；版本与状态带证据边界。端口区分监听地址、协议、发布/目标与访问用途；未关联监听登记为未知。只概括影响和缺口，完整镜像digest、挂载与命令留在详情或确切证据入口 |
| unit：成员、路径及配置消费字段 | 多成员能逐项比较管理对象、身份、版本、状态和证据。宿主程序、Swarm service/task、Compose及独立容器分清；原定义与运行基线的漂移单独列明。配置路径到包含文件、启动入口和消费者的关系可追踪；工作目录缺失不拿配置目录或登录目录代替 |
| unit：备份与恢复现状 | 数据、日志、备份分清；命名卷、匿名卷、bind及容器可写层分别说明风险。已验证恢复须给对象/来源版本/时间/结果；缺责任人、备份链或演练时逐项登记。敏感原件仅引用受控位置，Git投影不作恢复源 |
| unit：重复操作与缺口字段 | 每个操作可定位身份、目录、精确动作、预期结果及失败出口；候选写命令与已执行查询分开。没有可用探针、恢复命令或配置生效方式时列出具体阻塞及材料，不为凑齐操作写通用重启或猜测参数 |
| plan：步骤及推进条件 | 每步绑定方案版本、对象与前置状态，说明前后依赖、影响窗口、备份可用性、失败停止和条件回退；纯文档任务明确服务器无动作。修改方案不能回写已批准版本，方案存在不等于获批 |
| report：逐对象结果及交付范围 | 动作、配置差异、验证和证据能逐项对应；失败/跳过/回滚/未知保留。服务器状态、用户结果确认、文件归档和Git分别报告；没有远端动作不写成远端检查通过 |
| record：三个原文章节 | 保存实际需求、各版方案/批准、实际汇报/结果确认及其来源与完整性；不把可读汇报当作原始证据全集。汇报文件可供阅读，记录中仍保留当时文本或可核对的持久原文来源；不事后改写旧记录 |

### 单位操作覆盖与条件

单位操作至少核对下列查用路径；已存在的机制给精确入口，未核实机制保留对应操作中的阻塞说明，不生成假命令。升级、扩缩容、备份和恢复有真实机制或本次需求时才增加操作条目；否则在备份现状及缺口字段登记。

| 查用路径 | 必须回答的运维问题 |
| --- | --- |
| 状态查询 | 精确管理对象、限定字段、正常基线、退出结果及采样时点是什么；是否会输出环境值或敏感参数 |
| 健康判断 | 进程/副本、协议/接口、业务或数据分别验证到哪层；探针目标、认证安全引用及预期结果是否已有证据 |
| 启停与任务变更 | 原先运行/停止状态、依赖及顺序、维护窗口和中断影响是什么；任务重建、重启与整Stack发布有何不同；缺恢复条件在哪一步停止 |
| 配置核对与生效 | 原件及包含链、修改diff、配置检查、reload/restart/重建的实际支持方式、回读及失败恢复是什么；不能用投影覆盖原件 |
| 日志定位与排障 | 后端/路径、时间窗/条数、脱敏字段与读取权限是什么；权限不足、日志超限或后端未知时如何缩小或停止采集 |
| 备份恢复或升级扩缩容（条件成立时） | 版本/存储兼容、节点放置、复制与数据一致性、备份可用性、恢复点/恢复时长要求及演练证据是什么；不可逆处和停止条件在哪 |

验收时沿“总览单位 → 实际对象 → 配置/数据 → 状态命令 → 健康层级 → 失败/恢复”走读一个宿主服务和一个容器/Stack；若环境只有一种则说明覆盖范围。复杂单位逐项核对成员、镜像和挂载，条件不适用与信息缺失分别保留。已授权材料不足时交付具体缺口，不能以格式通过、监听存在或副本满足替代实际健康与恢复验收。

record 保留三个顶级章节；模板中的 `verbatim` 声明原文槽位，成品去掉该模板标记并使用足够长的普通文本围栏。原文自身的围栏和标题不改变，来源/时间/哈希在原文之外；含相同围栏时增长外层围栏。含秘密按留痕规则受控保存或明确脱敏，不靠格式要求越权归档。无原文写具体缺失，不编造方案或汇报。原始哈希应基于实际保存原文核对，格式检查不能证明批准真实性。

检查时使用共用检查器的 `--block access|index|unit|plan|report|record` 指定实际产物。JSON/YAML 机器文件仍消费既有命令策略及输入契约，不套本文报告骨架。
