## 填写与内容验收

实际任务的阶段记录统一消费 record 块，其他块只用于各自长期事实/策略文档，不自动全建。接入、盘点、变更、汇报和记录的触发与授权仍由主流程维护，目录见 [工作空间](workspace.md)，历史证据与纳管见 [留痕](records.md)。内容呈现统一消费全局输出规范，下表只补运维信息的归属和最低判据，不建立另一套排版规则。

### 各产物的信息落点

| 产物与落点 | 运维专属信息及验收 |
| --- | --- |
| access：身份、连接与撤销字段 | 能区分资产身份、登录账号、运行账号和提权边界；主机密钥的本地记录与可信确认分开。连接参数可定位到完整持久来源；授权必须对应真实来源、范围及失效条件，不能把历史批准转成长期许可 |
| index：导航表及跨服务字段 | 每个实际单位有稳定ID及详情入口；版本与状态带证据边界。端口区分监听地址、协议、发布/目标与访问用途；未关联监听登记为未知。只概括影响和缺口，完整镜像digest、挂载与命令留在详情或确切证据入口 |
| unit：成员、路径及配置消费字段 | 多成员能逐项比较管理对象、身份、版本、状态和证据。宿主程序、Swarm service/task、Compose及独立容器分清；原定义与运行基线的漂移单独列明。配置路径到包含文件、启动入口和消费者的关系可追踪；工作目录缺失不拿配置目录或登录目录代替 |
| unit：备份与恢复现状 | 数据、日志、备份分清；命名卷、匿名卷、bind及容器可写层分别说明风险。已验证恢复须给对象/来源版本/时间/结果；缺责任人、备份链或演练时逐项登记。敏感原件仅引用受控位置，Git投影不作恢复源 |
| unit：重复操作与缺口字段 | 每个操作可定位身份、目录、精确动作、预期结果及失败出口；候选写命令与已执行查询分开。没有可用探针、恢复命令或配置生效方式时列出具体阻塞及材料，不为凑齐操作写通用重启或猜测参数 |
| record：任务与当前状态、需求来源 | 顶部能定位当前阶段/版本、待批准项和下一步；实际需求及补充有原文和完整性说明。历史状态只在所属阶段解释，不与当前状态并列混用 |
| record：阶段的操作方案与审批记录 | 步骤覆盖对象/身份/连接、顺序、影响、备份、验证和条件回退；审批紧邻具体版本，保留真实渠道和答复、失效/撤销边界。先提交后执行，既有授权复用且不扩大；方案有文件或申请调用成功均不等于人工批准 |
| record：阶段的执行与验证、阶段结论 | 实际命令/工具、策略判定、时间/退出、文件映射和证据逐动作对应获批版本；未执行阶段明确无动作及原因。阶段结论就是汇报正文；没有远端动作不得写远端检查通过，未验证业务不得报业务健康 |
| record：最终结果与归档 | 服务器/业务状态、用户确认、文件归档、实际索引检查和Git分别报告；精确范围有用途和排除依据，批准原文绑定本次结果/提交范围，后续变更不能覆盖旧确认 |

### 单位操作覆盖与条件

单位操作至少核对下列查用路径；已存在的机制给精确入口，未核实机制保留对应操作中的阻塞说明，不生成假命令。升级、扩缩容、备份和恢复有真实机制或本次需求时才增加操作条目；否则在备份现状及缺口字段登记。

| 查用路径 | 必须回答的运维问题 |
| --- | --- |
| 状态查询 | 精确管理对象、限定字段、正常基线、退出结果及采样时点是什么；是否会输出环境值或敏感参数 |
| 健康判断 | 进程/副本、协议/接口、业务或数据分别验证到哪层；探针目标、认证安全引用及预期结果是否已有证据 |
| 启停与任务变更 | 原先运行/停止状态、依赖及顺序、维护窗口和中断影响是什么；任务重建、重启与整Stack发布有何不同；缺恢复条件在哪一步停止 |
| 配置核对与生效 | 原件及包含链、修改diff、配置检查、reload/restart/重建的实际支持方式、回读及失败恢复是什么；不能用投影覆盖原件 |
| 日志定位与排障 | 后端/路径、时间窗/条数、脱敏字段与读取权限是什么；权限不足、日志超限或后端未知时如何缩小或停止采集 |
| 备份恢复或升级扩缩容（条件成立时） | 版本/存储兼容、节点放置、复制与数据一致性、备份可用性、恢复点/恢复时长要求及演练证据是什么；不可逆处和停止条件在哪 |

验收时沿“总览单位 → 实际对象 → 配置/数据 → 状态命令 → 健康层级 → 失败/恢复”走读一个宿主服务和一个容器/Stack；若环境只有一种则说明覆盖范围。逐项核对单位成员、镜像和挂载，条件不适用与信息缺失分别保留。已授权材料不足时交付具体缺口，不能以格式通过、监听存在或副本满足替代实际健康与恢复验收。

record 使用上方完整统一骨架，不再提供独立 plan/report 块。需求、阶段及最终确认的重复项沿用固定结构和稳定标识，不按任务规模裁剪；动作尚未执行时，在“执行与验证”下写 `条目情况：无：本阶段未执行及具体原因`，不虚构动作。尚未形成方案、缺少批准或未汇报时在对应字段如实标缺口；各阶段提交的操作方案和已取得的原文决定保持原版本，当前状态与后续结果按实际进展维护。

模板中的 `verbatim` 声明逐字来源，成品去掉模板标记并使用足够长的普通文本围栏；原文内部标题和换行不变，来源/时间/哈希在围栏之外，涉及秘密按留痕规则处理。未取得原文或批准时保存明确缺失状态，不以示例代替事实；阶段汇报只在阶段结论维护一次。已存在的旧记录与附件按留痕的保留规则续接，不自动迁移或删除已批准内容。

检查时使用共用检查器的 `--block access|index|unit|record` 指定实际产物。JSON/YAML 机器文件仍消费既有命令策略及输入契约，不套本文报告骨架。除结构检查外，须人工核对待批准事项能定位具体版本、每个实际动作有有效授权和证据、当前状态与最终结果不矛盾；格式通过不验证审批真实性或实际运行结果。
