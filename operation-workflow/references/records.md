# 方案、执行记录与归档

本文定义任务留痕与文件纳管；目录见 [工作空间](workspace.md)，授权执行见 [主流程](../SKILL.md)。记录是历史证据，不授予后续权限。Markdown 产物的通用规范统一从 [固定模板](output-templates.md) 接入。

## 统一任务记录

项目及运维根明确后，在 `OPS_ROOT/records/` 排他创建 Asia/Shanghai 时间目录 `YYYYMMDDHHmm`，重名追加 `-01`、`-02`；多服务器及原任务中的初始化共用记录。目录未定先收集资料，确定后补存真实原文。

所有实际任务统一使用 [固定模板的 record 块](output-templates.md)，只维护一份 `record.md` 作为人工审阅和批准入口；不按任务规模、操作次数或复杂程度另选产物结构，不单独生成 plan、report。需求、各阶段方案、批准、实际动作、证据与结果在同一记录内就近关联，阶段重复使用同一结构。阶段尚未执行时保留明确的未执行说明，不创建虚构动作。

顶部只维护当前有效状态、待批准事项和下一步，指向具体阶段；历史阶段保留当时状态和证据，不能把旧的“待批准”“未执行”混作当前结论。阶段标识保持稳定，动作绑定所属阶段版本与批准来源，结果、归档和 Git 状态分别判断；字段与内容要求只在 record 模板维护，不另写状态台账。

## 原文、版本与审批关联

- 需求与用户决定保留真实原文，来源消息或工具回执、时间、版本、完整性及可安全取得的哈希放在原文之外；原文内部标题和换行不改写。不能取得完整原文或准确时间时分别标缺失，不用摘要冒充原文或猜测时间。含秘密按受控保存要求处理，无法安全保存则报告该部分未归档。
- 阶段操作方案在提交批准时固定内容和版本；已有批准不改写，修正或新增范围在同一记录追加阶段版本，写清与原版本的关系、变化及新批准范围。其余当前状态、执行证据和结果可继续更新，不以整份持续变化的 `record.md` 哈希标识已批准的方案；需要内容绑定时对该阶段方案片段或实际脚本单独标识。
- 人工申请统一遵守 [全局确认机制](~/ai-agent-config/config/force/collaboration-rule.md#需要先确认时)。在阶段内保存申请渠道、具体版本/范围和真实答复或可信回执，区分待答复、批准、拒绝、撤销和失效。
- 同一阶段以实际命令/工具参数、命令策略版本及判定、批准引用、起止时间、退出状态和结果串起执行链。服务器文件操作另记原始路径、类型、大小、权限/属主/时间、可安全取得的前后哈希、本地映射或排除原因；方案命令不冒充实际动作，本地格式检查不冒充远端验证。
- 阶段结论和最终结果就是汇报正文，直接展示对应记录内容，不再维护一份报告或在记录中复制报告全文。确有另行发送的原文需留存时，在所属阶段记来源及可核对的持久引用或原文，保留当时内容，不事后改写。

## 附件与既有记录

仅为正文无法替代的执行或证据需要保留附件：批准需绑定内容或实际执行的必要脚本、需独立核对的工具原始输出、文件基线/镜像，或有效项目契约及实际程序必须消费的机器文件。正文写明附件用途、对应阶段和定位，引用同一事实来源；不为每版方案另存策略判定 JSON，不把审批、执行和结果同时抄入多个文件。临时解析、语法试验、未采用草稿和一次性验证产物放项目约定的忽略目录，不进正式记录目录。

先复用既有执行入口；直接命令或工具参数可以在阶段内完整审阅时，不为留痕强制编写专用脚本。确需持久脚本时，在对应阶段标明候选/获批/已执行状态及路径、哈希，代码只保存一处，不在记录中另抄正文；批准前可审阅内容不等于已经执行。

已有记录、独立方案/报告及审批 JSON 保留可信原文和已批准版本，不因技能更新自动删除、改写或批量迁移。续接时在原 `record.md` 明确当前状态和既有材料位置，新增阶段消费统一契约；项目或程序要求的机器附件继续维护其唯一数据源。旧文档局部续写只核对新增内容与有效基线，不用新模板强迫重构历史。

## 文件镜像

- 仅纳管任务相关普通文件，原始大小须 **≤15,000,000 字节**。传输前后核验类型、大小、敏感性及漂移；超限、大小未知、秘密/数据备份不纳入内容，不靠压缩、分片、LFS 或脱敏变小绕过。超限只记元数据，不为算哈希读全文。
- 安全原件 `/etc/nginx/nginx.conf` 映射到 `servers/<server-id>/rootfs/etc/nginx/nginx.conf`；脱敏件加 `.redacted`，字段摘要加 `.summary.md`，不得用原配置名保存不可部署的投影。拒绝 `..`、跨 server-id 和本地祖先软链接逃逸。
- 软链接只记目标/元数据；设备、socket、FIFO、数据库数据目录不复制。私钥、密码、Token 和敏感原件即使很小也不进 Git。
- 首次修改前将合规基线存到本次 `baseline/<server-id>/rootfs/...`；已有 Git 基线仍核对远端漂移。最终回读写镜像，删除登记 tombstone；基线、附件和日志遵守相同大小/脱敏要求。
- 镜像不是完整备份，恢复所需权限/属主/ACL 等另记。真实备份按单位手册的受控位置维护；必要备份未验证时停止依赖变更。

## 结果审批与提交

证据形成即填入所属阶段；完成回读、敏感信息检查和映射，在同一记录汇总最终结果及精确拟提交范围后，按全局确认机制请求结果及归档提交确认。审批后漂移须补充确认；拒绝/待补充保留待处理状态，不自动回滚或抹掉失败证据。

保留用户改动，不擅自 stash/reset；无关 staged 不得混入。提交范围只包含统一记录及已说明用途的实际附件、手册和镜像，不附带临时产物。批准后仅暂存明确文件，不用 `git add .` 代替范围确认，然后运行：

```bash
python3 <技能目录>/scripts/check_archive.py index --repo <仓库根> --operations-root <仓库相对运维目录>
```

检查覆盖运维目录整个索引快照的路径、对象类型和大小，不检查脱敏、原始大小或审批真实性；这些人工核对。超限历史文件先取得处置授权，不擅自删远端或重写历史；记录过大转受控外部归档，不截断原文。

复用提交消息技能，核对 hooks/filters 等隐式动作，再提交获批内容并回查一致性。报告 commit ID，不在提交内预写自身哈希，也不为记录它反复 amend。Git 失败只标归档未完成，不自动回滚服务器；push 单独授权。
