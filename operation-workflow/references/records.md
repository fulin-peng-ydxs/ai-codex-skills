# 方案、执行记录与归档

本文定义任务留痕与文件纳管；目录见 [工作空间](workspace.md)，授权执行见 [主流程](../SKILL.md)。记录是历史证据，不授予后续权限。文档与确认规范从主流程接入。

## 审阅与执行分工

项目及运维根明确后，在 `OPS_ROOT/records/` 排他创建 Asia/Shanghai 时间目录 `YYYYMMDDHHmm`，重名追加 `-01`、`-02`；多服务器及原任务中的初始化共用记录。目录未定先收集资料，确定后补存真实来源。

实际任务统一消费[固定模板](output-templates.md)的 record、execution 块：`record.md` 是人工审阅入口，`execution.md` 是命令及来源证据的唯一明细。按模板中的任务类型选择是否需要方案；不为只读或已有授权的本地维护填服务器变更、备份和批准套话。先记录已知目标和真实需求，操作后保存实际命令、结果及必要来源；没有操作时明确原因，不造条目。技能讨论和审查不触发这些运维产物。

审阅记录必须自身足以决定是否批准：保留具体前后差异、影响与保障、执行顺序及结论，不能只剩链接。精确命令、原始来源和必要输出在执行明细中保存一处；审阅记录用方案编号、操作编号和具体链接定位，不复制代码或工具流水。按固定模板从当前决定导航到方案，再到操作及批准来源；导航是所属条目状态的摘要，不形成独立台账。历史方案的当时结论保留在所属条目，新增事实更新当前摘要，不把历史流水搬回顶部。

## 专项分析组合

运维诊断借用内存、安全等专项方法时，先区分辅助判定与用户要求的完整专项成果：

- 辅助判定融入现有两份记录。当前结论、处置决定和验证缺口在 record 的结论或所属方案结果中维护；执行证据在 execution 的所属操作中维护。内存风险保留稳定编号、等级及依据、证据状态、持有/增长/释放机制、触发及影响、建议、处理状态、处置决定及真实来源；代码版本与运行制品映射、未验证项分别说明。不因嵌入省略这些判断，也不称已交付专属技能的完整报告。
- 用户要求完整专项报告，或已有同范围专项正文需要延续时，按该技能的模板与维护主线更新其唯一正文；运维记录只保留当前决定、影响摘要和具体引用，不再复制整份分析。已授权的专项成果属于有独立消费方的附件，不受“不另建运维报告”限制。
- 同一风险的当前状态只在上述选定正文维护；旧操作中的当时状态作为历史证据保留，新结果链接其依据。续接先核对该正文和仍有效的历史风险，不因新任务目录重置编号或遗漏未处理项。

## 会话定位与续接

创建或续接任务记录时，核实当前工具名称、真实会话ID及可取得的会话链接，填入 `execution.md` 的“会话定位”字段。优先使用可信运行上下文或工具元数据；上下文未提供时，查询宿主可用的会话工具并核实当前会话归属。

ID与链接分别判断。仅在入口不可用、查询失败、查询后仍缺失或无法核实归属时，注明无法取得及具体原因；不能把尚未查询写成无法取得，也不猜测ID或拼造链接。

跨会话续接保留原项，追加新会话及其负责的方案、操作、决定来源或提交回报范围。会话信息仅用于定位，不代替批准原文或执行证据，也不能保证聊天长期可访问；不要求聊天导出或独立台账。

## 版本、来源与执行关联

- 方案使用稳定编号和版本，如 `S03/v1`；操作如 `O03`，来源如 `R01`、`A01`。方案链接操作，操作反向关联方案版本；批准绑定方案及其操作范围，来源只保存一次。链接定位实际条目锚点或持久证据的具体位置，不只指向目录或整份长文；标题/路径变化同步修正关联。名称不作为批准证明，执行者仍须核实真实来源。
- 提交批准时保留方案的目标、范围、步骤及关键条件；不要求预写或冻结命令。已批准的范围不改写。新增范围或实质变化追加版本，说明差异并取得相应批准。状态、结果继续按事实更新，不计算整份可变记录的哈希；已有版本引用能可靠定位时，不为每个消息、动作或输出另算哈希。脚本审阅与可执行边界见[命令策略](command-policy.md#执行方式)。
- 人工申请遵守主流程引用的全局确认机制。需求及影响授权的用户决定保留真实原文或可核验的持久回执，记录渠道及对应范围；不复制全部聊天。已有项目要求机器审批文件时引用其唯一来源，不再抄写一份原文。原文内部标题和换行不改写，时间不明不猜测，缺失和脱敏如实说明；秘密不进入记录。
- 执行以能独立判断结果和失败出口的操作单元组织，例如“核对挂载”可包含几条关联命令。不同目标、授权或失败会阻断后续的动作须可分别核对，不能合并后隐去中途失败。身份、连接、策略版本等共用信息保存一次，操作只补差异；具体字段由 execution 模板维护。
- 策略须在执行前核对；一组操作记录共同适用的版本、判定及批准覆盖关系，deny、例外或新增范围单列。不为每个 checker 调用保存 JSON，不为本地排版、解析及工具包装步骤建执行流水。
- 每个操作完成后汇总实际命令/参数、所用入口版本及结果，关联方案范围，不补造执行前命令清单。参数记真实取值；影响目标、范围或实质风险的变化先补充决定，不能事后改方案来匹配执行。当次命令答复的适用条件按[主流程审批判定](../SKILL.md#审批判定)处理；执行明细关联真实答复来源与执行结果，不另建批准文件，也不把方案批准当作命令已经确认。
- 操作结果形成即保存时点、退出状态及支持判断的关键输出；失败、部分完成、跳过和未知分别说明。保留关键失败证据及实际恢复状态，不靠最后一条命令成功推断全组成功。只记录有助判断的输出，不默认保存全量成功输出和轮询流水。源码证据给仓库、提交号、仓库内路径和必要片段；未提交内容注明差异及证据限制。绝对路径和 worktree 链接可辅助定位，不能是唯一复核依据；路径失效时保留原取证位置，补已核实的 Git 对象或持久片段，不把当前源码冒充历史版本。

## 附件与既有记录

附件只用于不能由两份正文替代的需要：有交付/复用价值或需固定执行内容的脚本、确需独立复核的原始证据、合规基线/镜像，或有效项目契约及实际程序必须消费的机器文件。写清用途和对应操作，不按执行轮次创建文件。脚本只保存一个正文，记录引用路径与版本/哈希，不另抄源码；未采用草稿、临时解析和一次性辅助产物进入项目约定的忽略目录。

既有记录、独立方案/报告及审批 JSON 不因技能更新自动批量迁移。续接及局部更新保留有效结构与当时批准范围；用户明确要求迁移旧结构时，采用当前模板，保持方案/操作/来源标识、已批准目标及步骤、命令参数、失败证据、真实决定原文和历史状态，修复受影响链接。迁移完成对照原文核对这些内容；只更新展示结构，不把本次编辑授权冒充旧任务的新执行、验收或提交批准。

## 文件镜像

- 仅纳管任务相关普通文件，原始大小须 **≤15,000,000 字节**。传输前后核验类型、大小、敏感性及漂移；超限、大小未知、秘密/数据备份不纳入内容，不靠压缩、分片、LFS 或脱敏变小绕过。超限只记元数据，不为算哈希读全文。
- 安全原件 `/etc/nginx/nginx.conf` 映射到 `servers/<server-id>/rootfs/etc/nginx/nginx.conf`；脱敏件加 `.redacted`，字段摘要加 `.summary.md`，不得用原配置名保存不可部署的投影。拒绝 `..`、跨 server-id 和本地祖先软链接逃逸。
- 软链接只记目标/元数据；设备、socket、FIFO、数据库数据目录不复制。私钥、密码、Token 和敏感原件即使很小也不进 Git。
- 首次修改前将合规基线存到本次 `baseline/<server-id>/rootfs/...`；已有 Git 基线仍核对远端漂移。最终回读写镜像，删除登记 tombstone；基线、附件和日志遵守相同大小/脱敏要求。
- 镜像不是完整备份，恢复所需权限/属主/ACL 等另记。真实备份按单位手册的受控位置维护；必要备份未验证时停止依赖变更。

## 结果审批与提交

完成回读、敏感信息检查和映射，在审阅记录汇总实际结果及文件范围；审批触发和覆盖范围统一消费[主流程的审批判定](../SKILL.md#审批判定)。未要求或明确拒绝提交时保持未归档，按实际验证交付任务结果，不反复索取提交批准，也不自动回滚或抹掉失败证据。待决定与必要门禁失败须区分，不能把拒绝提交记成执行失败。

保留用户改动，不擅自 stash/reset；无关 staged 不得混入。提交范围只包含审阅/执行记录及已说明用途的实际附件、手册和镜像，不附带临时产物。批准后仅暂存明确文件，不用 `git add .` 代替范围确认，然后运行：

```bash
<已核验Python绝对路径> <技能目录>/scripts/check_archive.py index --repo <仓库根> --operations-root <仓库相对运维目录>
```

检查覆盖运维目录整个索引快照的路径、对象类型和大小，不检查脱敏、原始大小或审批真实性；这些人工核对。超限历史文件先取得处置授权，不擅自删远端或重写历史；记录过大转受控外部归档，不截断原文。

结果与本地归档批准可一次取得，答复后继续完成暂存、门禁和提交，不停在写回确认。批准来源及归档状态的预期回填属于已展示文件范围的收尾，无须因此重新申请；新增文件或实质内容变化按主流程只补新增差异。仅确认结果或拒绝提交不等于归档获批，必要门禁失败也不能提交。

复用git-commit-message-authoring生成提交消息，核对hooks/filters等隐式动作，再提交获批内容并回查一致性。失败在已有record.md写准确原因、当前步骤及具体恢复路径；恢复后复用有效批准继续，不复制另一份归档任务。Git失败不自动回滚服务器；push单独授权。

提交终态采用“记录内封存状态、提交外实际回报”：提交前完成批准来源、门禁结果和状态回填，按[会话定位与续接](#会话定位与续接)复核会话信息，由审阅记录关联负责提交回报的会话，再校验、暂存并复检最终快照。本记录自身尚未提交时如实写“已获批，待随本快照提交”；其他仓库或既有提交已完成时可记录其真实ID，不能混称本记录已提交。

commit成功后核对实际ID、提交文件范围及获批范围内无未提交残留，在最终会话答复报告仓库、commit ID、本地提交结果与推送状态；失败则报告实际失败或未执行项。该提交外回报与Git历史共同构成提交完成证据，不能仅凭封存记录的文字判断终态。不为把自身ID或“已提交”回写原记录而再改文件、amend或增加记账提交；已有外部回执可直接引用，不新建回执体系。跨仓库提交逐项报告实际结果，不以一个成功掩盖其他失败。
