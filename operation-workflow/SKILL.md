# 运维操作

## 职责与边界

本技能维护执行顺序和授权节点。[工作空间](references/workspace.md) 定义初始化、清单和手册；[命令策略](references/command-policy.md) 定义通配规则与判定工具；[留痕](references/records.md) 定义统一任务记录、附件和归档。环境事实保存在目标项目。

## 输入与前置条件

确定项目目录、环境、服务器/服务、目标及成功标准。优先复用会话、清单和手册，只追问缺项。

## 执行流程

根据任务选择执行分支：

- 讨论、审查技能或方案：对话交付，不连接、不创建操作记录。
- 空项目、无服务器资料、目标未接入或必要入口/策略缺失：先按工作空间初始化；资料不足待补充，空模板不能冒充完成。
- 已有证据足够的本地文档维护：完成下方共用准备后更新受影响文件，进入汇报归档，不执行远端步骤。
- 只读排查/盘点：批准连接检查方案 → 采集 → 汇报归档。
- 服务器改动：连接检查 → 变更方案 → 批准执行 → 验证汇报 → 归档。

实际任务先读取目标策略、相关手册及留痕要求，检查 Git 基线，在同一份 `record.md` 保存需求、当前状态和后续各阶段。人工确认前读取 [全局协作规则“需要先确认时”](~/ai-agent-config/config/force/collaboration-rule.md#需要先确认时)，确认渠道、降级和答复效力统一遵守该入口；申请绑定记录中的阶段/版本或最终确认范围。所有实际任务使用同一记录契约，不按规模或复杂程度拆分产物。初始化及生成/维护手册时读取工作空间要求；变更只补任务需要的事实。

1. **准备连接检查**：在记录的检查阶段写明目标/环境、账号、渠道、主机密钥核验、凭据引用、检查命令和范围，并按全局确认机制申请。连接与需确认的检查合并为有明确边界的申请；已有覆盖的授权直接复用。未获批准不连接。
2. **连接并检查**：核验主机、账号和环境；每个动作先匹配命令策略。将批准、实际动作、证据及结果填入同一阶段。只执行白名单或已获批动作，补充诊断只确认新增范围；不因重连或命令拆分重复申请有效授权。只读任务完成后进入第 5 步。
3. **提交变更方案**：在同一记录新增变更阶段，写明文件 diff/精确命令、顺序、影响、备份、失败停止条件、回退和验证，再申请该阶段版本的批准；批准后才能修改。一次批准覆盖所列命令、验证及条件回滚，不逐条询问；方案变化新增阶段版本并只确认新增差异，不另建方案文件。
4. **执行与验证**：重查目标和文件/运行状态基线，漂移影响方案时暂停；先验证必要备份，再按获批顺序实施。逐动作在所属阶段记录结果和证据，按成功标准检查业务。失败只做获批回滚并验证；结果未知先核实，不盲目重试。回读文件、更新镜像及受影响手册后，在该阶段填写结果并更新记录顶部当前状态。
5. **汇报并取得结果确认**：以同一记录的阶段结论和最终结果展示实际改动、验证结果、失败/未执行项，以及文档/镜像 diff、排除项和拟提交文件，申请结果与归档提交确认；不另建报告文件。只读任务明确无服务器变更。待确认不妨碍保存证据，也不触发自动回滚。
6. **归档提交**：核对获批内容没有漂移，按留痕门禁暂存精确范围；复用 `git-commit-message-authoring` 生成消息，再本地提交。push 另需明确授权。审批后出现新差异先补充确认，不覆盖获批内容。

## 核心约束

- 连接授权按任务操作范围约定有效期与重连边界，遵守用户明确限制的次数或时限；身份不符、主机指纹变化时停止依赖动作。
- 凭据只用安全引用；主机密钥从可信来源核验，不关闭校验、不默认提权。只读也须限定敏感字段、输出量和资源开销。
- 命令通配免除逐条确认，服务器变更仍先批准整体方案；文件工具、上传下载、SQL/API 写入按相同副作用判定。禁止项不能被普通任务批准覆盖。
- 策略脚本只读配置和命令文本，不执行命令、不验证审批真伪、不提供系统级隔离；包装命令和脚本须展开审阅内层动作。

## 产出边界与交付

交付唯一任务记录 `record.md`、必要手册/镜像和已有 commit ID；方案、批准、执行和结果在记录内按阶段关联，不并行维护 plan/report 或多份状态台账。附件条件与既有记录保留按[留痕](references/records.md)执行；分别说明服务器结果、人工确认、归档和 Git 状态。

新建或整体重构 Markdown 运维产物前读取 [固定产物模板](references/output-templates.md)，按实际交付块填充。原文保存和局部更新保留基线；既有授权、命令策略及归档门禁继续执行。

## 验证与完成标准

失败/取消保留证据，未完成审批或提交不称完整闭环；未做业务检查不称业务验收通过。

交付前从记录顶部定位当前阶段和待批准事项，再沿同一阶段核对方案版本、批准来源、实际动作、验证和结果；检查历史状态没有冒充当前状态，附件都被正文引用。归档须通过 `python3 <技能目录>/scripts/check_archive.py index --repo <仓库根> --operations-root <仓库相对运维目录>`；它仅检查索引路径、类型和大小，不能替代敏感信息、授权或远端结果核实。

完整生成或整体重构运维产物后运行 `python3 <skills-root>/skill-authoring-standard/scripts/validate_document_template.py <产物路径> --template <本技能目录>/references/output-templates.md --block <实际产物块>`；格式检查不能代替授权、内容及实际运行结果核实。
