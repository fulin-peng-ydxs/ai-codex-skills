# 开发留痕产物模板

本文件维护产物结构与字段；适用条件、最低内容、固定项和完成标准由 [技能入口](../SKILL.md) 维护。按入口的对应分支读取；章节组织按入口声明的结构策略调整，不因迁移模板省略业务字段。

## 开发留痕报告

```markdown
# 功能需求

## 功能的详细需求

- 写清楚业务目标、使用场景、输入输出、边界条件和用户可见行为。
- 如果需求来自开发计划或会话补充，融合成当前最终口径。

## 功能开发的实际结果

- 写清楚当前代码实际完成了什么。
- 列出关键业务文件及各自承担的职责。
- 如有未完成、暂未覆盖或依赖外部条件的部分，明确说明。

## 功能开发的具体实施方案

- 按实现链路描述具体怎么做：前端入口、状态/表单/交互、接口调用、后端接口、服务逻辑、数据查询、异常处理、配置等。
- 只写与本功能有关的实现细节，避免泛泛描述。
- 如果复用了原开发计划，说明最终实现与计划是否一致，以及差异点。

## 性能与安全落实情况

### 性能与容量

- 对照需求目标和开发计划，记录实际采用的查询、索引、分页/分批、缓存、异步、事务、远程调用、资源释放、前端加载与渲染、降级或监控等适用方案，并列出关键文件、模块或配置。
- 记录真实执行的数据量、负载条件、命令/工具、指标口径、基线与变更后结果。未执行性能或容量验证时，说明原因、可能影响和后续验证位置，不得写成已达标。

### 安全、权限与数据保护

- 对照需求目标和开发计划，记录认证、功能权限、数据范围、输入/文件校验、敏感数据与日志、凭据、审计、重放或滥用防护等适用措施的真实落点和失败边界。
- 记录已执行的正反向测试及结果。未执行安全验证时，说明未验证范围、风险和后续处理；不得用“代码已实现”推导“已通过安全验证”。

### 方案偏差与剩余风险

- 说明实际落地与需求目标、开发计划的差异、原因、影响范围、补救/回退方式和剩余风险。
- 如本次确实不涉及性能或安全改动，分别写明判断范围和代码、需求或计划依据；仍要记录对现有性能与安全边界的影响判断。

## 上线部署操作

- 列出本功能上线时需要配套执行或确认的非代码产物，例如 SQL 文件、配置文件、环境变量、脚本、字典、菜单权限、定时任务、第三方平台配置等。
- 对每个配套项写明文件或配置位置、用途、执行或生效方式、目标环境，以及是否必须上线前执行。
- 如果本功能不涉及上线部署配套操作，明确写“本次无额外上线部署操作”。

## 验证情况

- 列出本次确实执行过的验证命令、脚本或检查结果。
- 如果未执行验证，说明原因；如果验证失败或存在阻塞，说明失败点和影响范围。
- 不得把未执行的验证写成已完成。
```
