# 页面 UX 审查清单

审查时使用本清单。只报告影响可用性、一致性、清晰度、稳定性或造成不必要复杂度的问题。

## 1. 范围与证据

范围、项目依据与证据选择按技能正文执行。对照原型或改动前页面时，比较同一任务、可比状态下的信息顺序、层级、间距、控件对齐与操作线索；响应式变化按设计意图判断。

## 2. 风格统一

按用户可观察的效果检查同角色一致性，保留有任务依据的差异；实现是否重复和是否违反契约分别交给复用与合规审核。

检查：

- 页面标题区、工具栏、筛选区、内容区、分页、空状态、弹窗、抽屉、标签页、表格、卡片、表单是否和同类页面一致。
- 同一含义的按钮是否使用一致的颜色、尺寸、图标风格、顺序、禁用态、加载态和危险态。
- 同排同角色控件在实际渲染中比较字号、字重、行高、高度、圆角、内边距和基线；源代码用了相同 class 仍可能被继承或媒体查询覆盖。不同角色可有明确层级，文字不同不必机械等宽。
- 表格是否使用一致的行高、表头样式、排序提示、对齐、空态、加载态、分页和操作列行为。
- 表单是否使用一致的 label 位置、宽度、间距、必填标记、placeholder、校验时机和错误位置。
- 状态标签、徽章、状态点、chip、风险标签、结果文字是否共享语义颜色和形态规则。
- 弹窗和抽屉是否共享宽度、标题层级、内容 padding、footer 布局、滚动行为和关闭行为。
- 空状态的语气、层级、恢复入口是否与同类任务一致。

## 3. 布局与信息层级

检查：

- 首屏是否展示真实工作区或核心内容，而不是装饰、空白或大段说明。
- 用户是否不用读长文就能识别页面目的、主要内容、主操作和次操作。
- 相关控件和内容是否自然分组。
- 列、卡片、表单行、按钮、表头、操作区是否对齐稳定。
- 间距是否来自小规模尺度，不随机忽大忽小。
- 页面密度是否符合产品类型；管理、数据、研究、仪表盘、运营工具应紧凑、安静、可扫描。
- 滚动归属是否清楚，避免多个嵌套滚动区互相抢滚动。
- 固定区和滚动区是否有意设计；关键筛选、表头、分页、操作 footer 不应意外消失。
- 卡片是否只用于独立内容块，而不是装饰每一个页面 section。
- 避免卡片套卡片、边框过多、阴影过重、大面积无效空白和装饰容器。
- 加载、hover、切换 tab、筛选变化、刷新数据时，容器尺寸是否稳定。

## 4. 颜色与视觉语义

检查：

- 主色、次色、成功、警告、危险、禁用、选中、hover、focus 是否有稳定含义。
- 颜色是否与项目已确立的视觉角色一致；token 的实际消费方式由合规或复用审核判断。
- 文字和图标在常规、hover、选中、禁用、深浅主题下是否清楚可辨；分别检查文字对背景、图标内部符号对填充色的对比，不能因强调色鲜明就判可读。警告色取自项目语义约定，不自行规定黄色或橙色。
- 危险操作是否明确，但不在非当前任务中抢占注意力。
- 同一状态是否在不同页面使用同一颜色。
- 图表、徽章、标签、状态点是否必要时配合文字或形状，不只靠颜色传递关键信息。
- 渐变、强阴影、装饰背景、高饱和色块是否干扰工作内容。

## 5. 字体与可读性

检查：

- 页面标题、分区标题、正文、表格文字、标签、辅助说明、数字是否层级清楚。
- 运营和后台页面不使用 hero 级标题或营销式文案塞进紧凑面板。
- 长文本是否有明确处理：换行、省略、tooltip、popover、抽屉、详情页或列展开。
- 按钮文字、表头、标签、弹窗标题、字段 label 是否不溢出容器。
- 数字、日期、百分比、金额、数量、状态是否便于比较。
- 高密表格对齐是否一致；可比较数字列应统一对齐。
- 输入控件的边界、内部文字起点、辅助说明及错误文本是否按同一角色对齐；单行内容检查文字垂直中心，不能仅以外框居中作结论。数字输入与列表比较按任务确定对齐，不机械统一左右方向。
- 辅助说明是否短且靠近对应控件。

## 6. 交互直观性

检查：

- 布局或交互改造中，用同一用户任务比较前后入口可发现性、点击/展开层级、是否离开当前任务及返回后的草稿、选择和位置保留。记录增加或减少的实际负担及其任务依据，不把点击数越少机械当作越好。
- 核心操作是否因视觉收敛被藏入辅助配置；区域标题、控件位置及当前值能否帮助首次使用者判断在哪里操作，是否需要靠长说明才能找到入口。
- 主区、辅助区及详情是否重复同一内容或要求反复选择同一对象；辅助查看和配置是否能在约定上下文中完成。控件可点击、链路可完成只证明功能可用，不能代替上述体验比较。

- 主操作是否明显，次要和低频操作是否降级。
- 按钮文案是否描述结果，而不是只有模糊动词。
- 新建、编辑及补充流程中，同角色主次操作的位置、顺序与可达性是否可预期；差异是否有任务依据，不能仅因一个操作区固定、另一个自然滚动就判缺陷。
- 纯图标按钮是否有 tooltip 或足够上下文。
- 搜索、筛选、重置、保存、取消、删除、导入、导出、排序、分页、列设置是否出现在用户预期位置。
- 表单是否有 label、必要 placeholder、校验、提交反馈和恢复路径。
- 弹窗和抽屉是否有清晰标题、关闭路径、主按钮、次按钮和提交中状态。
- 标签页、步骤、筛选、分页、排序、列设置的状态保留或重置是否可理解。
- 破坏性操作是否在必要时确认或提供恢复路径。
- hover、active、focus、selected、disabled、loading、success 状态是否可见。

## 7. 操作与控件必要性

- 沿同一用户意图检查现有入口，核对频率、位置、发现成本及重复路径是否有用途；建议合并时实际验证保留入口可发现、可操作且反馈清楚，不以按钮数量定级。
- 用支持的输入方式操作文字、状态、行和按钮，检查命令与导航是否可区分、触摸是否依赖 hover、权限/危险/异步命令是否被含糊入口替代。
- 切换编辑与阅读态，检查仅服务编辑的分类、提示、必填标记及空工具区是否退出布局和焦点路径；唯一值、单位、关系和阅读操作是否保留，切回编辑后入口与状态是否恢复。
- 分别检查保存中、加载中、前置条件不满足和权限受限，避免把临时禁用误判为阅读态；静态检查未覆盖切换时说明缺口。

## 8. 状态完整性

按交互设计清单选择任务与控件状态，实测进入、转换、退出及恢复；增加长文本、极端值、慢网络和请求失败条件。检查空数据与筛选无结果是否可区分，错误可否重试，禁用原因是否可理解，加载是否保留必要占位；只测默认态不能判状态完整。

## 9. 动画与反馈

检查：

- 动画是否说明状态变化，而不是装饰页面。
- 动画时长是否适合高频工作。
- 加载、骨架、过渡、展开收起、弹窗、抽屉、菜单是否不闪烁。
- hover、加载、切换 tab、筛选、刷新时是否没有布局跳动。
- 高频工作界面是否避免吸引注意力的动效。
- 反馈是否不会阻塞无关操作，除非动作确实必须阻塞。

## 10. 说明与指引

检查：

- 必要说明是否靠近相关控件。
- 复杂控件是否有简短 helper text、tooltip、hint 或示例。
- 首次使用概念是否有帮助入口，但不把文档铺满页面。
- 指标、比较结果与解释入口是否对应同一范围或局部选择；位置是否让用户误以为说明属于另一项读数。按阅读和对照需要判断就地说明、展开或弹层，不把单项折叠本身定为缺陷。
- 空状态、错误、破坏性操作、不可逆操作、权限受限状态是否解释清楚。
- 不用长文案弥补命名、布局或交互设计的问题。
- 按钮是否夹带挤压主操作的解释；就近帮助、确认和结果反馈是否各承接适当信息。影响决定的后果是否在执行前可见，不能只在成功后告知；简单操作是否被无必要的二次确认打断。
- 避免用可见文字解释显而易见的 UI 行为。
- 提示是否讲清当前结果与下一步，而不是堆叠浏览器存储、安全上下文等实现术语；备份、草稿与正式提交的结果是否区分清楚，避免把局部失败说成整次操作失败。
- 提示位置及视觉强度是否匹配影响范围、严重程度和恢复需要；字段错误应能定位并访问对应字段，页面次要信息不应反复打断填报。详情折叠后，关键结果与恢复入口是否仍可发现，不强制所有提示放标题或全部自动消失。
- 相同任务的搜索提示、字段帮助和动作名称是否跨页面一致；不同结果不能为了文案统一而混淆。

## 11. 响应式与视口

按共用验证方法确定目标视口。在支持范围内检查文字可读、操作目标、导航、表格、筛选、弹层、横向溢出和文字重叠；不把未声明的移动支持当作缺陷。

## 12. 任务状态与连续性

### 密度、数字与语义色

- 在最窄支持视口使用长值、多条件和错误态，检查固定区扣除后的正文空间、条件可见及可编辑性、命中区和必要分组；比较主命令与工具、统计与说明的层级，确认压缩未移除必要功能。
- 比较数据范围条件与展示工具、无数据/不可计算/零值、唯一选项的入口，观察用户能否预测作用，是否存在重复占位与无效选择。
- 用整数、非整数、零值、长值及未完成小数输入检查填报、编辑和报表；在支持主题下比较摘要、卡片、排行、图表的实际颜色及邻近标签/符号，核对精度、对齐和语义是否一致，不以 class 名证明呈现。

### 滚动与内容可达

- 用短长内容分别滚到顶部、中部、末端，检查固定区、分页、最后一项、导航/安全区占位及透明区域点击；观察提示的出现、消退、再次滚动与页面隐藏后清理。
- 对长列表、候选列表执行继续浏览和搜索，区分容器裁切与服务端数量限制；检查真实后续状态、分页默认/禁用/加载及点击命中、末尾反馈与同类列表是否一致。

### 顺序调整（涉及时）

- 分别在分组、分页和筛选状态下调整顺序，检查入口、允许范围、预览和保存结果；用非拖动路径验证同一操作能否完成。
- 所有顺序调整均验证保存中重复或冲突操作、取消与失败后的状态恢复或保留、保存成功后刷新或重进的结果；持久化算法与权限交业务/代码审核。
- 采用拖动时另查有效落点、边界滚动、拖出和取消，以及结束后是否误开详情。

### 输入、弹层与反馈

- 覆盖入口与内部输入的焦点交接、候选浏览、搜索、选择、取消、外部点按、字段切换及离开返回；观察选值/草稿、双重强调、强制失焦、关闭后抢焦点或自动重开。
- 按项目约定逐一操作关闭按钮、遮罩、返回和键盘取消；增加正文拖出、遮罩滑动和关闭子层的同一次点击，检查是否误关父层、穿透底层或绕过未保存/提交中保护。
- 从父任务进入子层再取消，检查父草稿、位置和焦点；分别触发成功、失败和父对象失效，检查重试/取消、过时详情收束，以及辅助命令使用已保存值还是编辑值的线索。
- 在短抽屉、低高度、长候选和错误态下，检查完整候选行、搜索、清除与动作是否可达；取消搜索不得误清选值。异步候选、过渡与适用的键盘往返后再次检查锚点、裁切、内部滚动及反复缩小/换向/跳动。
- 实际触发成功与失败，比较提示出现/消失前后的正文、工具栏和主操作位置；在嵌套弹层中检查消息、恢复入口、阅读时间与关闭影响。指针/焦点离开、触摸结束、数据变化和页面隐藏后核对瞬态反馈清理及持久选择保留。
- 在支持主题下检查点击/按下/聚焦/选中时的边框、圆角、高亮、底色漏出、焦点裁切和残留遮罩，区分有意样式与缺陷。

### 导航与恢复

- 首次进入、滚到中部切页返回、下钻返回、再次滚动再返回，覆盖数据延迟和刷新接替；核对草稿、条件、选择、位置、隐藏页浮层和活动资源，包含受影响共享消费者。
- 结束来源任务或重置条件后从常规导航重进，检查来源标记、返回入口和记忆地址是否复活或形成循环，按契约区分重置条件与结束来源。
- 对可选浏览器能力的失败检查实际访问方式、反馈与主操作是否可继续；尺寸断点与平台/API 能力分别取证，不把当前测试入口外推到所有环境。

## 13. 触摸与原生输入

仅在目标平台和受影响能力涉及时执行；混合输入设备保留指针与键盘验证。

### 触摸意图

- 快速滑动、到顶/到底后继续、反向拖动，观察惯性、局部边界反馈、滚动传递和固定区移动；复测修复后是否生硬。
- 覆盖短按、长按、拖动取消和结束，检查误开详情/菜单及替代入口；诊断选区、点击高亮与焦点边框，复核输入和正文复制、键盘焦点仍可用。
- 从图表区域开始滚动，检查误选/下钻、完整读数入口和手指遮挡，不能只验证 hover。

### 原生输入与软键盘

- 在目标平台比较普通输入、原生日期/时间、选择器和帮助文本的起点、基线与垂直中心；覆盖聚焦缩放、连续点按及主动缩放。
- 完成键盘展开、收起、再次聚焦的往返，包含字段切换、底部字段及区域展开；检查遮挡、页头位移、底部空白、位置恢复和旧修复干扰新焦点。
- 系统键盘或原生控件限制按目标版本官方资料或实测判定；不把自绘输入或原生容器替换当作无感修补，也不靠禁用缩放掩盖布局问题。

## 14. 问题质量

按技能正文定级并交付位置、现象、影响、证据和修复方向。不得以个人审美、纯业务逻辑批评或无依据的大重做代替体验问题；能复用现有入口解决时，不建议增加复杂 UI。
