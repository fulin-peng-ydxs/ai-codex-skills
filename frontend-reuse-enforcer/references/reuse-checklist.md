# 前端复用优先清单

用于前端开发和代码审查。目标是防止页面私有实现、重复组件、重复状态逻辑和重复样式持续增长。

## 1. 查找入口

开发前先查：

- 同目录页面和组件。
- 全局组件目录、业务组件目录、布局组件目录。
- hooks/composables、utils、api helpers、constants、schemas、formatters。
- 全局样式、主题 token、设计系统、组件库、页面模板。
- 测试 helpers、fixtures、mock builders。
- `DESIGN.md`、页面规范、组件清单和项目级 AI 指令。

搜索线索：

- 页面标题、按钮文案、弹窗标题、空态文案。
- 字段名、接口参数、状态码、枚举值、标签文案。
- class 名、CSS 变量、颜色值、尺寸值。
- 表格列名、筛选项名、表单字段名。
- 函数名、事件名、store 字段、hook/composable 名。

## 2. 第二次出现判定

以下情况视为第二次出现，需要复用判断：

- 两个页面有相似筛选栏、工具栏、表格外壳、分页、操作列。
- 两个弹窗/抽屉有相似标题区、表单结构、footer、提交/取消逻辑。
- 两个页面有相似空态、加载态、错误态、权限态、提交中态。
- 两处代码有相同字段格式化、单位展示、枚举文案、状态颜色、tag/badge 映射。
- 两处有相同打开/关闭、提交、重置、排序、选择、批量操作或权限状态处理。
- 两处接口调用有相同参数归一化、分页参数、排序参数、错误处理。
- 两处测试重复构造相同用户、列表数据、表单数据或页面状态。
- 两处样式重复表达同一种布局、间距、颜色语义或响应式策略。

判断重点是“同一变化原因”，不是代码是否完全一样。

同一操作角色也适用：同排工具入口、主次保存动作、可编辑条件等先识别角色，再复用样式；不因标签字数不同各写字号、字重或内边距，也不把所有角色强制画成相同大小。

移动 App/PWA 还检查滚动容器、位置提示、可见视口/键盘适配、固定操作占位、焦点交接、提示清理、草稿失败反馈与触摸图表行为。两个页面表面不同但依赖同一状态流或生命周期，也属于复用判断范围；具体尺寸、时序和交互策略来自项目规范。

## 3. 抽取类型选择

按最低必要层级抽取：

- 只是展示结构重复：抽展示组件。
- 展示结构重复且需要局部自定义：抽组件 + props/slots。
- 行为逻辑重复但 UI 不同：抽 hook/composable。
- 纯函数逻辑重复：抽 util。
- API 参数、分页、排序、筛选重复：抽 API helper 或 query builder。
- 表格列、筛选项、表单字段重复：抽 schema/config/factory。
- 状态文案、颜色、图标重复：抽 status map 或状态组件。
- 样式组合重复：抽 class/token/mixin。
- 测试准备重复：抽 fixture/test helper。

## 4. 抽象质量要求

好的复用单元：

- 名称描述稳定语义，而不是描述当前页面。
- 默认值覆盖主流场景。
- 差异点有明确 props、slots、options、callbacks 或 schema。
- 调用方代码比复制实现更短、更清楚。
- 两个以上消费点都能保持原行为。
- 测试覆盖共同逻辑和至少一个差异点。

坏的复用单元：

- 需要大量布尔参数才能工作。
- 把多个不相关职责塞进一个组件或 hook。
- 为了复用泄漏调用方内部状态。
- 让调用方传入整块临时 JSX/template 才能拼出页面。
- 命名绑定某个页面，却被多个模块使用。
- 抽象后每次新增差异都要改核心实现。

## 5. 复用实施步骤

1. 先锁定已有实现和新增需求的共同变化点。
2. 选择抽象层级。
3. 创建复用单元，保持 API 小而清楚。
4. 迁移旧使用点。
5. 接入新使用点。
6. 删除重复代码和页面私有样式。
7. 补测试或更新现有测试。
8. 若项目要求，更新 DESIGN、组件清单、文档或组件预览。
9. 运行项目要求的验证命令。

样式复用还需核对实际结果：在相关视口比较同角色控件的字号、字重、行高、高度、圆角、内边距与对齐；检查页面选择器、继承、媒体查询和全局覆盖是否造成分叉。文字不同可按内容自适应宽度，不机械要求所有按钮等宽；命中区与可见底板尺寸分别检查。共享组件改动覆盖已有消费者，包括抽屉、编辑或隐藏后返回的使用点，按影响选择，不扩展为无关全站审查。

### 共享行为与消费者验证

- 先追踪谁消费共享入口、谁仍有私有计时器/监听/状态、谁通过 props、slot、样式或断点绕开入口；组件已抽取但旧使用点未迁移，仍可能造成分叉。
- 按共同变化点选择消费者：例如滚动共享能力覆盖相关页面正文和弹层，输入共享能力覆盖新增与编辑；不以一个默认使用点通过代表所有场景。
- 核对资源所有权：同一视口或输入状态是否只有一份权威来源，订阅和清理是否成对；页面隐藏、返回及最终卸载是否清理或恢复计时器、观察器、异步查询与瞬态提示。
- 对滚动、键盘、焦点与图表触摸行为，验证状态链和真实操作结果；同样的组件名、DOM 状态或 CSS 声明不能证明原生交互一致。
- 对表单帮助、草稿及失败反馈，确认共享的是稳定状态与恢复流程；文案、对齐和交互角色允许项目规定的差异，不用大量布尔配置强行合并不同语义。
- 长列表修复追踪管理列表、候选和日常列表的共同滚动、分页与末尾反馈入口；统一呈现不等于强制相同分页机制或批量大小，区别由实际加载契约承接。
- 数值规则追踪展示、编辑回填、模板回填、草稿恢复及图表读数等消费者；复用精确格式化入口，保持业务计算与未完成输入的边界，避免各页面复制正则或浮点转换。
- 语义颜色同时追踪映射来源与消费者选择器，比较实际主题结果；统一 token 或 class 后，局部高优先级样式仍可能造成分叉。
- 导航位置共享的是状态来源与恢复时机，普通缓存返回与显式下钻返回保留各自语义；核对路由监听、激活刷新和异步完成是否重复恢复旧位置，不为单页缺陷新增第二套全局滚动状态。

## 6. 不抽取说明

不抽取时在实现说明或审查结论中给出理由，不因此自动新建计划或过程文档。可接受理由：极短且无稳定语义的表达、领域语义或生命周期不同、需求尚不稳定且有后续合并点、违反分层或形成循环依赖、抽象配置成本高于维护收益。不能以“先复制快一点”“只改一个页面”“以后再抽”或细微样式差异代替判断。

不抽取时说明：

- 重复点是什么。
- 已检查的同类实现在哪里。
- 为什么不是同一变化原因。
- 为什么抽取会增加复杂度或破坏分层。
- 后续第几次出现或哪个条件满足时再抽取。

示例：

```md
未抽取：两个页面都有“导出”按钮，但一个是同步下载，一个是异步任务创建并轮询进度，生命周期不同；当前只复用按钮样式，任务逻辑不合并。若后续出现第二个异步导出流程，再抽 `useAsyncExportTask`。
```

## 7. 审查定级

- `P0`：重复实现导致行为不一致、页面不可用、关键状态错误或测试失败。
- `P1`：已有明确复用组件/工具却新增页面私有实现；第二次出现但没有复用判断；重复逻辑会造成维护分叉。
- `P2`：重复样式、字段映射、状态文案、表格列、筛选配置或测试 helper，短期不阻断但会扩散。
- `P3`：可后续收敛的小重复或命名/抽象边界优化。

## 8. 和其他技能的边界

- 页面体验是否合理：交给页面 UX 审查。
- 是否遵循 DESIGN 文档：交给 DESIGN 遵循审查。
- 本清单只判断复用、重复、抽象边界和维护分叉风险。
