# README 输出契约

## 适用规则

新建、重构或系统性优化 `README.md` 时，默认遵守本契约。用户明确指定其它结构，或仓库已有必须保持的公开模板、社区规范或机器读取契约时，可以偏离；偏离项和原因必须在交付说明中列出。

标题语言跟随文档语言。中文使用下述固定标题；用户明确要求英文时，使用文末给出的英文标题。除上述例外外，不新增其它 Markdown 二级章节，不给固定章节改同义标题。项目特有内容放入语义最接近的固定章节下，使用三级或更深标题组织。

## 固定章节与顺序

一级标题固定为项目名称。一级标题之后先写一段不超过三个自然段的导语，说明项目的一句话定位、主要读者或使用场景；不要在导语中堆叠完整技术栈。

二级章节使用以下完整顺序：

```markdown
# {项目名称}

## 项目概览
## 核心能力与适用边界
## 快速开始
## 使用说明
## API 与 CLI
## 架构与代码结构
## 配置与环境变量
## 数据准备与迁移
## 开发与验证
## 部署与运维
## 故障排查
## 兼容性
## 文档导航
## 贡献指南
## 许可证与引用
```

其中以下六章是核心章节，必须保留且不得为空：

- `项目概览`
- `核心能力与适用边界`
- `快速开始`
- `使用说明`
- `开发与验证`
- `文档导航`

其余是条件章节，仅在触发条件成立时写入，但一旦写入必须位于上述固定槽位。README 面向真实读者，条件不成立时直接省略，不写空章节或只有“不适用”的章节。

## 核心章节最低内容

### 项目概览

至少说明项目解决的问题、主要使用者或调用者、核心运行形态和明确边界。项目状态、部署状态或成熟度只有存在权威事实源时才写。

### 核心能力与适用边界

至少列出一项可验证能力，并说明其入口、输入或使用场景、主要产出。业务应用强调用户闭环，库强调公共 API，服务强调对外契约，CLI 强调命令与输入输出，Monorepo 强调子项目职责。不得把规划能力写成现有能力。

### 快速开始

提供从干净环境到最小可用结果的最短路径，至少包括：

1. 前置运行时、工具或外部依赖；
2. 安装或依赖准备；
3. 启动、执行或调用命令；
4. 成功判定方式；
5. 长期服务的停止或清理方式。

所有作为常规流程推荐的命令必须通过 `command-verification.md` 的验证门禁。门禁未通过时不得落地 README。

纯文档、静态资源或其它没有安装、启动过程的项目，仍保留本章，改为说明获取、查看或使用最小产物的路径，并用仓库事实明确不存在对应命令；不得为了满足结构虚构安装或启动步骤。

### 使用说明

至少给出一条从入口到结果的完整真实路径。应用写用户操作闭环，服务写最小请求与响应，库写最小调用示例，CLI 写典型命令与产物，Monorepo 写子项目组合运行方式。不要与“快速开始”重复安装步骤。

### 开发与验证

按项目实际列出测试、静态检查、格式化、构建或打包命令，写清工作目录、适用范围和成功判定。只写已通过本次验证门禁的常规命令；没有某类能力时说明项目事实，不编造替代命令。

### 文档导航

列出当前真实存在的权威文档及职责，至少覆盖与本项目实际相关的 README、AI 协作、架构、设计、API、部署或需求入口。不得生成死链接，也不要复制下游文档正文。只有当前 README 可作为入口时，明确说明尚无独立专题文档。

## 条件章节触发规则

| 章节 | 写入条件 | 最低内容 |
|---|---|---|
| `API 与 CLI` | 项目向用户或其它系统暴露 API、SDK 或 CLI | 入口、主要调用方式、输入输出、详细契约链接 |
| `架构与代码结构` | 存在多个运行单元、明显分层、多个包，或读者需要据此定位改动 | 组件职责、关键调用关系、必要目录及边界 |
| `配置与环境变量` | 运行依赖非默认配置、配置文件、环境变量或密钥占位 | 配置入口、是否必需、默认行为、敏感信息边界 |
| `数据准备与迁移` | 依赖数据库、样例数据、模型文件、迁移或初始化脚本 | 前置条件、执行顺序、成功判定、数据影响 |
| `部署与运维` | 仓库存在正式部署、镜像、编排、发布或服务生命周期材料 | 构建产物、部署入口、健康检查、日志、停止或回滚入口 |
| `故障排查` | 存在当前项目可证实且可操作的常见故障 | 现象、检查顺序、日志或状态入口、恢复方式 |
| `兼容性` | 库、插件、SDK 或多平台项目存在明确兼容范围 | 运行时、框架、平台或协议兼容矩阵及依据 |
| `贡献指南` | 仓库接受协作开发且存在真实分支、提交、检查或评审规则 | 最小贡献流程及权威规则入口 |
| `许可证与引用` | 存在许可证、第三方资产、论文、数据集或引用义务 | 许可证文件和必要归属说明，不自行判断授权范围 |

条件章节不因“可能有用”而加入；必须存在代码、配置、文档或用户要求作为触发依据。

## 常见扩展内容归属

不为下列内容新增 Markdown 二级章节，按固定归属使用三级标题或短段落：

| 内容 | 固定归属 |
|---|---|
| 截图、演示地址、界面预览 | `使用说明`；仅用于快速识别产品时可在 `项目概览` 放一张主图 |
| 技术栈和版本 | 运行前置版本放 `快速开始`，组件职责和实现版本放 `架构与代码结构` |
| 登录、权限、测试账号使用方式 | `使用说明`；账号来源和敏感信息边界放 `配置与环境变量` |
| 开发硬约束 | `贡献指南` 只写摘要，并链接 `AGENTS.md` 等权威入口 |
| 路线图或维护状态 | 仅在有权威维护信息或用户明确要求时放 `项目概览` |
| 变更记录 | `文档导航` 链接真实 changelog，不复制历史流水 |
| 致谢、第三方资产和引用 | `许可证与引用` |

## 项目类型适配

项目类型只改变固定章节中的内容重点，不改变章节名称、顺序和职责：

| 项目类型 | 核心能力重点 | 使用说明重点 | 架构重点 |
|---|---|---|---|
| 应用 | 角色、页面、业务结果 | 最小用户闭环 | 前端、后端、数据和外部服务 |
| 服务 | API、任务、事件 | 最小请求或任务链路 | 接口层、服务层、存储和依赖 |
| 库或 SDK | 公共 API、扩展点 | 安装、导入和调用示例 | 包结构、兼容边界和扩展机制 |
| CLI 或自动化 | 命令、参数、输入输出 | 典型命令和产物 | 命令入口、处理阶段和文件边界 |
| Monorepo | 子项目和共享包职责 | 组合启动或独立使用 | workspace、依赖方向和构建顺序 |

一个仓库同时符合多种类型时，以主要交付形态为主，在对应章节补充其它形态，不新增额外 Markdown 二级章节。

## 更新已有 README

- 保留仍与代码和配置一致的有效事实，将内容移动到固定信息归属；不能为了套骨架删除项目特有能力、边界或使用说明。
- 合并重复章节，同一事实只保留一个主说明位置，其它位置使用链接或短引用。
- 旧标题与固定标题语义相同则统一为固定标题；项目特有标题降为对应章节下的三级标题。
- 删除空章节、占位符、历史流水、过期命令和没有事实依据的宣传内容。
- 重构前后必须回查仓库内指向 README 锚点的链接；锚点变化造成引用失效时同步更新。

## 交付门禁

落地前必须确认：

- 固定核心章节完整、非空且顺序正确；
- 条件章节均有触发依据且位于固定槽位；
- 没有额外 Markdown 二级章节、同义重复章节或占位内容；
- 命令验证门禁已经通过；
- README 内部链接和被本次标题调整影响的仓库内链接有效；
- 已运行 `scripts/validate_readme_structure.py <README-path>` 并通过；存在已说明的用户或仓库结构例外时使用 `--custom-structure`。
